- `stroke-outlines.tsx`의 `use client` 선언을 import 앞에 배치했다.
- 획 보조 모듈 38개의 타입 추론·선택 필드·SVG 부모 타입을 수정했다. 고정 획 상수의 초기화 값은 이전 커밋과 정확히 같다.
- Next.js는 `tsconfig.build.json`으로 배포 코드 전체를 엄격하게 검사한다. 실험 초안·테스트·작업 스크립트는 이 검사 대상이 아니다. 기존 `pnpm typecheck`의 전체 검사 범위는 변경하지 않았다.
- 프로덕션 빌드는 `next build --webpack`을 사용한다. 데이터 검증 조건을 완화하지 않았다.

## Turbopack JSON 정밀도 문제

Next.js 16.3.3의 Turbopack 빌드에서 batch1527의 JSON import가 원본 숫자 `14.091883092036781`을 `14.09188309203678`로 변환했다. 같은 모듈의 JavaScript 검증 상수는 원래 값을 유지하여 정확 비교에 실패했다.

위치는 `釁`의 `outlines[24][2].revealStartGate.firstProjection`이다. 원본 JSON과 원본 검증 상수는 일치하고, 원본 모듈은 Node에서 정상 로딩된다. 변환된 번들에서 두 값을 격리하여 불일치를 재현했다. `arguments.length` 검사는 정상적인 일반 함수로 보존되어 원인이 아니었다.

Webpack은 동일한 데이터와 검증 함수로 페이지 생성을 완료했다. 향후 번들러를 바꿀 때는 이 정확 비교를 유지한 채 전체 빌드로 확인해야 한다.
