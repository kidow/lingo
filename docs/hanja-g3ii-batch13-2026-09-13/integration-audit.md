# Batch13 통합 전 읽기 전용 감사

기준 커밋은 `390bea3c4659784a9ecdae7b01011912f292f94d`다. 현재 코드는 **비상교육 영상 근거만 표현한다**. 동양북스 PDF를 등록하려면 별도 문서 근거 타입과 검증 분기가 필요하다. 이 감사에서는 공유 코드·런타임을 수정하지 않았고 새 글자를 승인하지 않았다.

실제 Node 런타임과 카탈로그를 읽어 다음 수를 확인했다.

| 구분 | 글자 수 | 기준 획수 |
|---|---:|---:|
| 이번 검토 阿·兔 | 2 | 16 |
| 국내 전체 필순 부족 訣·紋·森·笛·蹟·稚·楓 | 7 | 88 |
| 기존 보류 奔·慈·遷·追·弊·透·響·還·蓮 | 9 | 126 |
| 3급Ⅱ 미적용 합계 | 18 | 230 |

전체 카탈로그 5,978자 중 런타임 1,472자, 한국어문회 근거 503자, 비상교육 근거 969자다. 3급Ⅱ는 500자 중 482자 적용 상태다. 기존 보류 9자는 문서의 검토 집합이며, 현재 Vivasam 레지스트리의 `conflict: 2`와 같은 숫자가 아니다.

[기존 공개 묶음](../../public/hanja-strokes/textbook-reviewed.json)의 SHA-256은 `aed1c17aa0a024f21015b9fcfb5661d7bb14d878c73560944c3e8efa1b442b12`다. 阿·兔는 런타임·교재 검토 대장·보정 레시피·직접 작성 레지스트리에 없다.

A의 fresh corpus 검토에서 阿는 Ko 없음, Ja 8획, MM 7획이다. MM은 왼쪽 첫 두 경계를 한 획으로 합친 후보여서 Ja 8획이 우선이다. B의 兔 검토는 Ko 없음, Ja/MM 각 8획이나 국내 PDF와 상단 순서·형태가 달라 보류 가능성이 높다. 이 감사 시점에는 둘 다 최종 경로·방향 승인이 아니다.

院·河·何와 免·逸·晩의 승인 경로는 존재한다. 부수 기하를 가져올 수 있다는 사실만으로 새 글자의 순서를 승인할 수는 없다. 阿는 정확 글자 Ja 후보가 있어 부수 합성과 직접 작성 레지스트리 확장이 필요하지 않다. 兔의 근거 충돌은 획 순서 교환이나 부수 합성으로 해소된 것으로 취급하지 않는다.

최소 변경안은 다음과 같다.

1. 기존 `HanjaTextbookStrokeData`와 Vivasam 969개 묶음을 유지하고, `verificationSource: 'dongyang-hanja3-note'`인 `HanjaDocumentStrokeData`를 별도 union 분기로 추가한다. 최종 경로·geometry SHA·recipe SHA·원본 획 매핑을 기록하고, 문서 참조에는 PDF SHA·PDF/인쇄 쪽·정확 글자·누적 칸 수·방향 근거 SHA를 넣는다.
2. 문서 검토 대장과 생성/검증 함수를 분리한다. 공식 ZIP/PDF의 URL·해시·바이트 수, 첫 한 획부터 전체 획까지의 누적 칸 매핑, 별도 공식 방향 자료의 정확 글자와 모든 stroke track 대응, 검토자·날짜·순서/방향/경계/자형 일치를 검사한다. 하나라도 미확정이면 공개하지 않는다.
3. 阿 좌표 보정이 필요하면 `sourceDocumentSha256`과 원본 medians SHA에 묶인 명시적 문서 레시피를 쓴다. `normalizeMedians`를 재사용할 수 있다. PDF 해시를 기존 `sourceVideoSha256`에 넣거나 기존 레시피의 canonical 형식을 바꾸지 않는다.
4. 별도 작은 문서 묶음을 명시적으로 런타임에 합친다. 일반 `auditStrokes`의 검증 분기·출처 집계도 새 출판사 근거를 인식해야 한다. 한국어문회 근거로 떨어지는 분기는 허용하지 않는다.

현재 `validateTextbookReview`는 Vivasam ID, XLSX 해시·행·영상명, 해당 행의 MP4 URL, 영상 검토 방식, 각 획 완료 시각과 길이를 요구한다. `textbookCorrection`과 직접 작성 경로도 영상 SHA에 묶여 있다. 이러한 조건을 PDF 때문에 약화시키는 방식은 피한다. 한 글자만 통과해도 이 한정된 분리는 가능하지만, 범용 출처 프레임워크나 새 부수 작성 체계까지 넓힐 필요는 없다.

기존 CLI의 로컬 입력은 `--manifest-file` XLSX뿐이고 세 후보 corpus는 매번 내려받는다. 새 문서 검사는 기존 ZIP/PDF 경로를 읽기 전용으로 받거나 공식 ZIP을 RAM으로 수신하되, 캐시 여부와 무관하게 전체 해시·크기를 확인해야 한다. 지정된 PDF 엔트리를 크기 제한 아래 RAM에서 읽고 원본을 저장소에 복사하지 않는다. 앞선 수신은 기본 TLS를 유지한 플랫폼 curl로 성공했으며 인증서 검증을 끄는 대안은 필요하지 않다.

구현 후 검증에는 잘못된 출처·페이지·글자·단계·방향 매핑·원본/레시피/출력 해시의 거부, 실제 생성 경로 재현, 새 출처 집계, 기존 1,472개 경로 보존, Vivasam 기존 테스트와 묶음 check 유지가 필요하다. 이후 영향 테스트·타입 검사·새 문서 묶음 check·프로덕션 빌드를 수행한다. 이 문서는 **통합 전 감사**이며 그 구현 검증을 완료했다고 주장하지 않는다.

阿만 통과하여 적용하고 兔를 보류로 확정하면 런타임 1,473자, 출판사 근거 970자, 3급Ⅱ 483자가 된다. 남은 17자는 자료 부족 7자와 보류 10자(기존 9자+兔)다. 아직 적용되지 않은 예상값이며 현재값과 구분한다. 세부 입력 핀과 감사 결과는 [integration-audit.json](integration-audit.json)에 기록했다.
