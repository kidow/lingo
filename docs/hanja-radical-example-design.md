# 한능검 예시 단어·부수 해설 설계

2026-09-17 인터뷰 기록. 결정만 적고 구현은 아직이다. 미정 항목은 끝에 둔다.

## 배경 (코드 사실)

- `HanjaCharacter.example`과 소개 카드 렌더링은 이미 있다 ([lib/hanja.ts](../lib/hanja.ts), [components/hanja/card.tsx](../components/hanja/card.tsx)). 5,978자 중 8급 10자만 채워져 있고, 2026-09-06 프로토타입 때 넣은 것이라 출처 기록이 없다.
- 부수는 배정한자 XLS의 `부수` 열 글자만 있다. 213종 중 168종은 배정자라 공식 훈음이 있고, 45종(疒 匚 虍 攴 广 网 丿 宀 辵 匸 儿 囗 冫 彳 尢 勹 豸 凵 冖 隹 彐 丨 亠 廾 彡 巛 厂 禸 幺 廴 丶 襾 卩 癶 屮 隶 亅 髟 鬥 厶 气 夊 爿 黹 龠)은 배정자가 아니다.
- XLS에는 `음표` 열도 있다. `scripts/hanja-source.py`가 읽지만 JSON에는 넣지 않는다.
- 퀴즈 정답 뒤 화면은 우하단 급수 뱃지만 있다.
- 한국어문회 자료실에서 "부수"를 찾으면 배정한자 XLS·HWP 2건뿐이고 "자원"은 0건이다. 한자어 예시·상형 해설은 한국어문회에 없다 (2026-09-17 확인).

## 결정

### 예시 단어

1. **출처는 국립국어원 사전**(표준국어대사전, 우리말샘 오픈 API). 한국어문회 자료에는 한자어가 없다. 표기·독음·뜻풀이는 사전 그대로 옮기고, 각 예시에 `source: { dictionary, entryId, url, verifiedAt }`를 남긴다. 우리말샘은 CC BY-SA·공공누리 1유형이고 인증키가 필요하다. 표준국어대사전 이용 조건은 착수 전에 확인한다.
2. **고르는 규칙** (스크립트가 결정적으로 고른다):
   - 구성 한자 전부가 그 글자의 읽기 급수 이하 배정자.
   - 2음절 한자어만.
   - 표준국어대사전 표제어만. 우리말샘 사용자 등재 항목 제외. 한자 표기가 정확히 일치.
   - 후보가 여럿이면 목표 글자가 첫 글자인 것 우선, 그다음 사전 등재 순.
   - 조건에 맞는 게 없으면 비워 둔다. 상위 급수 글자를 섞지 않는다.
3. **글자당 1개.** 타입은 지금의 `example` 하나를 유지한다. 배열은 필요해질 때.
4. 기존 10자는 같은 규칙으로 다시 고르거나 지운다.

### 부수 해설

5. 단순 훈음이 아니라 **상형문자 관점의 해설**을 붙인다.
6. **출처는 說文解字 원문.** 퍼블릭 도메인 원전. 부수마다 許慎의 원문을 인용하고 우리말 번역을 병기한다. 번역은 우리 작업이므로 원문을 항상 같이 보존한다. 說文의 풀이가 갑골문 연구와 어긋나는 글자도 그대로 인용하고 고치지 않는다.
   - 검토했지만 택하지 않은 것: 臺灣 教育部 異體字字典(결국 說文 재인용, 중국어, 이용 조건 미확인), Wiktionary(기관 아님), 자형별 부수 명칭(삼수변·물수 구분은 XLS에 없어 지어내게 됨).
7. **범위는 부수 213종만.** 글자 5,978개 각각의 자원 해설(校 = 木을 따르고 交가 소리)은 후속.
8. 부수 훈음은 168종은 배정자 자체에서 찾고, 45종만 표준국어대사전 부수 표제어(엄호·갓머리·병질엄·책받침 등)로 보완한다.
9. 저장은 글자마다 복제하지 않고 `content/hanja/radicals.json` 한 벌. 필드는 부수 글자, 훈음(또는 사전 명칭과 출처), 說文 원문·출전(卷·部), 번역, 확인일.

### 화면

10. **퀴즈 정답 뒤**: 보기 그리드 아래에 부수 블록. 왼쪽에 부수 글자 크게, 오른쪽에 `부수 나무 목` + 번역 한 줄. 급수·획수는 지금처럼 그림 칸 우하단 뱃지(`8급 · 10획`). 목업 C안.
11. **說文 원문은 번역 아래 작은 글씨로 한 줄** 같이 보인다(`說文 · 冒也。冒地而生。…`). 탭해서 펼치는 식 아님. 근거가 학습자에게도 보이게.

12. **소개 카드 순서**: 훈음 → 급수·획 줄 → 부수 블록(10과 같은 모양, 원문 줄 포함) → 예시 단어. 목업 A안.
13. **예시 단어에는 사전 뜻풀이를 싣지 않는다.** 한자어 표기 + 독음 + 구성 글자의 훈음만(`學校 학교` / `배울 학 · 학교 교`). 구성 글자 훈음은 배정표에서 렌더 시 찾고 저장하지 않는다. 사전은 표제어 존재·한자 표기·독음 확인에만 쓴다. 따라서 `example.meaning`은 없앤다.

### 데이터 파이프라인

14. **사전은 표준국어대사전 오픈 API**(`https://stdict.korean.go.kr/api/search.do`). 키는 `.env`의 `STDICT_API_KEY`. `.env.example`에 이름만 적는다.
15. **한자로 역검색은 안 된다** (2026-09-17 확인). `target=2`(원어)는 무엇을 넣어도 0건이고, `q=校`는 서버가 `q=교`로 바꿔 표제어를 찾는다. `wildcard`도 0건.
    - 그래서 **2음절 한자어 전체를 첫 음절별로 한 번 긁어 로컬 캐시**로 둔다: `advanced=y&type1=word&type2=chinese&letter_s=2&letter_e=2&method=start&q=<음절>&num=100`으로 100건씩 쪽을 넘긴다. **`start`는 건수가 아니라 쪽 번호다**(`start=2`가 101~200번째). 건수로 알고 101을 주면 빈 본문이 와서 첫 쪽만 남는다 — 처음에 그렇게 100건씩만 받아 8급 校에 軍校가 붙었다. 첫 음절은 배정한자 5,978자의 음 472개 + 두음법칙 변형(녀→여, 로→노 등) = 477개.
    - 캐시는 `.cache/stdict-start-<음절>.json`(CC-CEDICT와 같은 자리, gitignore 됨). 저장소에는 고른 결과만 들어간다.
    - 고르기는 캐시에서 로컬로: `origin`이 정확히 한자 2자, 둘 다 허용 급수 안, 목표 글자 포함. 목표 글자가 첫 글자인 것 우선, 전문 분야(`cat`) 없는 일반어 우선, 그다음 `target_code` 오름차순(대체로 가나다순). 독음은 사전의 `word`를 그대로 쓴다(두음법칙은 사전이 이미 반영). 같은 표기의 동음이의어(家敎 ×2)도 같은 순서로 하나만.
    - **표준국어대사전만으로는 "흔한 말"을 고르지 못한다.** 빈도가 없고 `target_code`는 가나다순도 아니다(學人 358821 < 學校 361333). 검색 결과에 전문 분야(`cat`)도 오지 않는다. 첫 수집(2026-09-17)은 8급에 九六·南小·女靑·學人 같은 낯선 말을 붙였다.
    - 그래서 **한국어기초사전**(국립국어원, 학습자용 5만 낱말, CC BY-SA 2.0 KR)의 **등급과 많이 찾은 순서를 앞세운다.** 이 사전은 원어를 한자로 바로 찾는다(`advanced=y&target=4&lang=2&method=include&q=校&sort=popular`, 응답 XML, `word_grade` 초급/중급/고급). 글자마다 한 번 물어 `.cache/krdict-origin-<글자>.json`에 둔다. 키는 `.env`의 `KRDICT_API_KEY`. 후보는 여전히 표준국어대사전 표제어 가운데서 고르고, 순서만 초급 > 중급 > 등급 없음 > 고급 > 기초사전에 없음 → 목표 글자 첫 글자 → 용례 많은 순 → `target_code`다. 「없음」은 韓國·中國 같은 고유명사에 붙는 값이라 고급 앞에 둔다(뒤에 두면 韓에 韓日이 붙는다). 같은 등급에서는 용례 수가 흔한 말을 가른다(父母 18 · 父女 6).
    - 기초사전 API는 짧은 간격으로 백여 번 부르면 **접속을 네 시간쯤 끊는다**(2026-09-17 두 번: 35번째, 1초 간격으로도 115번째. HTTP 오류가 아니라 TCP 무응답). 글자마다 한 번씩 5,978번은 그래서 못 한다. 대신 **사전 전체 XML**(사이트 하단 「사전 전체 내려받기」, LMF 형식, CC BY-SA)을 `.cache/krdict-xml/`에 두고 읽는다. 파일이 있으면 API를 부르지 않는다. 파일에는 「많이 찾은 순」이 없어 그 자리는 용례 수가 대신한다. 처음엔 2019-08 판 미러(github.com/spellcheck-ko/korean-dict-nikl-krdict)로 돌렸고, 그날 공식 2026-08-19 판(53,671 항목)으로 바꿨다. 2026판은 등급을 훨씬 넓게 매겨(2019판은 대부분 「없음」) 같은 등급이 흔해, 용례 수 순서가 그때 들어갔다.
    - `example`은 `{ word, reading, source: { dictionary: '표준국어대사전', targetCode, url, verifiedAt } }`.
16. **說文 저본은 위키문헌(zh.wikisource.org) 說文解字 大徐本.** 부수마다 卷·部·URL과 가져온 본문의 SHA-256을 `radicals.json`에 남긴다. 45개 배정 외 부수의 명칭은 같은 API로 확인한다 (`엄호` → 원어 `广戶`, target_code 460196 확인).
17. 스크립트: `pnpm hanja-examples [급수…]` (사전 캐시·선택·JSON 쓰기), `pnpm hanja-radicals` (說文 원문 수집·검증). 둘 다 `pnpm check`에 무결성 검사를 붙인다: 모든 부수에 항목이 있는가, 45개는 사전 출처가 있는가, 예시의 두 글자가 급수 규칙을 지키는가.

18. **표준국어대사전 이용 조건**: [저작권 정책](https://stdict.korean.go.kr/join/copyrightPolicy.do)에 따르면 별도 표시 없는 텍스트 자료는 CC BY-SA 2.0 KR, 상업적 이용 포함, 저작자 표시 필수 (2026-09-17 확인). 우리는 표기·독음·표제어 번호만 가져오고 뜻풀이·용례는 싣지 않는다. 각 예시의 `source`에 사전 이름과 URL을 남기고, 한능검 트랙 설명 또는 별도 고지에 저작자 표시를 둔다.

19. **說文 번역 검수**: 번역 213개를 `docs/hanja-radicals-shuowen-2026-09-17/README.md`에 표(부수·훈음·원문·번역·卷部·URL)로 남기고, 원문과 재대조한 뒤 바로 커밋한다. 사용자는 나중에 표를 훑고 이상한 것만 고친다. 커밋 전 승인 대기나 급수별 분할은 하지 않는다.
20. 예시는 지금처럼 `content/hanja/characters/g*.json`의 `example`에 둔다(별도 파일로 빼지 않음). 쓰기 전에 `pnpm pending --free`로 다른 세션이 그 파일을 쥐고 있는지 본다.

21. **화면에 저작자 표시를 두지 않는다.** 혼자 쓰는 프로젝트이고 글자마다 같은 문구가 반복되기 때문. 출처는 데이터의 `source`와 이 문서에만 남긴다. 說文 원문 줄(11)은 출처 표시가 아니라 해설의 일부라 그대로 둔다. CC BY-SA의 저작자 표시 조건은 공개 배포 시점에 다시 본다.

## 구현하며 정한 것 (2026-09-17)

- 번역은 `content/hanja/radical-translations.json`에 손으로 쓰고, `pnpm hanja-radicals`가 `radicals.json`에 합친다. 원문 텍스트가 바뀌면 번역도 다시 본다 — 테스트가 두 파일이 같은지 본다.
- 부수 훈음은 저장하지 않고 `lib/hanja-radicals.ts`의 `indexRadicals`가 배정표에서 찾는다. 한능검 청크는 이미 배정자 전체를 품고 있어(`components/hanja/shell.tsx`) 카드가 그 색인을 써도 새로 내려받는 게 없다.
- 說文에 없는 부수는 亠·爿 둘. 康熙 자형과 다른 아홉은 說文 자형으로 찾았다(尢→尣, 彐→彑, 冫→仌, 巛→川, 歹→歺, 靑→青, 无→旡, 廾→𠬞, 阜→𨸏). 위키문헌이 尤를 尢로 적어 두어 康熙 자형을 먼저 찾으면 엉뚱한 글자에 걸린다.
- 배정 외 부수 45자의 명칭은 표준국어대사전에서 45자 모두 확인했다. 사전은 큰입구몸을 ‘口’, 스물입발을 ‘卄’으로 적어 두어 그 자형도 함께 대조한다.
- 검수표는 `docs/hanja-radicals-shuowen-2026-09-17/README.md`. 스크립트가 만든다.

## 구현 순서

1. `lib/hanja.ts`: `example`에서 `meaning` 제거, `source` 추가. `HanjaRadical` 타입과 `content/hanja/radicals.json` 로더.
2. `scripts/hanja-radicals.ts`: 위키문헌에서 213 부수의 說文 원문 수집·해시. 168종 훈음은 배정표에서, 45종 명칭은 사전 API로. 번역은 손으로 채우고 표 문서 생성.
3. `scripts/hanja-examples.ts`: 첫 음절별 2음절 한자어 캐시 → 규칙대로 선택 → `g*.json`에 씀. 기존 10자 교체.
4. `components/hanja/card.tsx`: 부수 블록 컴포넌트(부수 글자 크게 · 훈음 · 번역 · 說文 원문 줄). 소개 카드는 훈음 → 급수·획 → 부수 블록 → 예시(표기·독음·구성 글자 훈음). 퀴즈 정답 뒤에는 보기 아래 부수 블록.
5. `pnpm check`·`lib/*.test.ts`에 무결성 검사. 문서 갱신 후 커밋·푸시.
