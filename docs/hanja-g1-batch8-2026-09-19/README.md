# 1급 槃~訃 50자 검토 — 50자·632획 반영

2026-09-19 · **50자 반영, 보류 없음**

[1급 7차 挽~駁](../hanja-g1-batch7-2026-09-18/README.md)의 `next-batch.json`에 고정한 후보 50자를
같은 방식으로 대조했다. 첫 대조에서 40자가 일치했고, 10자는 보정 후 전체 획을 다시 확인했다.
허가된 중간선 626획을 유지하고 6획을 국소 보정했으며, 7자의 획 순서를 바꿨다.
MM 원본 45자, Ja 원본 5자에서 출발했다.

## 보정

| 보정 대상 | 변경 |
| --- | --- |
| 礬·攀 | 樊의 爻 넉 줄을 왼쪽 木보다 먼저 (1~4획과 5~8획 묶음 교환) |
| 尨 | 彡 석 줄을 尤의 점보다 먼저 (4~7획 재배열) |
| 槃 | 舟의 아래 안쪽 점을 긴 가로보다 먼저 (5·6획 교환) |
| 魃·魄 | 鬼의 田 안쪽 가로를 안쪽 세로보다 먼저 (4·5, 9·10획 교환) |
| 駙 | 馬의 왼쪽 세로획을 윗가로획보다 먼저 (1·2획 교환) |
| 絆·畔·拌 | 半의 丷 두 점을 바깥쪽으로, 왼쪽 점은 왼쪽 아래·오른쪽 점은 오른쪽 아래로 반전 (7·8 / 6·7 / 4·5획) |

같은 회차의 蟠처럼 田의 안쪽 가로가 이미 세로보다 앞선 글자와,
醱·潑·撥의 發, 癖·劈·闢·擘·璧의 辟, 幇·陪·賻(Ja 원본)처럼
순서와 방향이 모두 같은 글자는 그대로 뒀다.

부수 유사성으로 승인하지 않았다. 각 글자의 사전 전체 필순을 순서대로 보고,
색으로 나눈 25% 진행 구간에서 방향·펜 떼기·획 경계·완성 자형을 대조했다.
보정 10자는 변경 획뿐 아니라 전체 획을 재대조했다.

[direction-probe.mjs](direction-probe.mjs)가 60°를 넘는 획 18개(10자)를 표시했고,
10자 모두 보정으로 이어졌다. 표시만 되고 그대로 둔 획은 없다.
舟·樊·鬼·馬처럼 덩어리로 얽힌 자리는 획 끝점 좌표를 숫자로 확인한 뒤 판정했고,
槃의 舟는 획을 확대해 점·가로·점의 대응을 다시 맞췄다.
畔의 오른쪽 점은 60°로 표시 임계 바로 아래였지만, 시트에서 왼쪽 점과 같은 반전으로 읽혀 함께 보정했다.
45~60° 구간의 방향 차이는 21개였고 그중 이 한 획만 보정했다.
나머지 20개는 대부분 사전이 세로로 긋고 허가 원본이 기울여 쓰는 짧은 점으로,
이전 회차와 같은 기준으로 임계 아래는 허가된 중간선을 그대로 뒀다.
이번 회차 원문은 모두 `translate(0, -y)`만 쓰고 가로 이동이 없다.

## 근거와 재현

- [observations.json](observations.json): 50자 판정, 10자의 첫 판정·보정·재대조 기록, 8방향 코드

- [originals.json](originals.json): 고정한 라이선스 원본의 중간선과 정규화 경로

- [candidate-paths.json](candidate-paths.json), [review.json](review.json): 승인 경로와 증거 해시
- [prepare.mjs](prepare.mjs): 읽기 전용 승인 데이터 재현 (50자 승인을 검사)
- [verify.mjs](verify.mjs): 재현 결과·공개 데이터·적용 수·다음 후보 검증. 1급 회차의 보류 글자는 큐에서 뺀다
- [checks.json](checks.json), [progress.json](progress.json): 이번 검증과 전체 진행 현황
- [next-batch.json](next-batch.json): 다음 腑~娑 50자·609획 후보
- [acquire.mjs](acquire.mjs), [source-checks.mjs](source-checks.mjs), [serve.py](serve.py): 원본 고정·원문 확인·검토 시트

재생 중간선은 Arphic Public License의 고정 MM·Ja 원본에서 출발했다.
사전의 경로·마스크·영상·스크린샷을 파일에 저장하거나 배포하지 않았다.
