# 1급 稠~纂 50자 검토 — 48자·612획 반영, 嗔·朕 보류

2026-09-20 · **48자 반영, 2자 보류**

[1급 15차 謫~糟](../hanja-g1-batch15-2026-09-20/README.md)의 `next-batch.json`에 고정한 후보 50자를
같은 방식으로 대조했다. 첫 대조에서 41자가 일치했고, 7자는 보정 후 전체 획을 다시 확인했으며, 2자는 자형 차이로 보류했다.
승인 48자에서 허가된 중간선 610획을 유지하고 2획을 국소 보정했으며, 6자의 획 순서를 바꿨다.
MM 원본 43자, Ja 원본 7자에서 출발했다.

## 보류

嗔은 사전이 眞의 위를 匕(오른쪽 위에서 시작하는 납작한 삐침과 갈고리 乚)로 쓰는데
허가된 MM 원본은 真으로 그려 十(긴 가로와 그것을 가로지르는 세로)이다.
朕은 사전이 왼쪽 月 안을 오른쪽 아래로 떨어지는 점 둘로 쓰는데 허가된 MM 원본은 가로 둘이다.
둘 다 순서·방향 조정으로 메울 수 없는 자형 차이라 贖·猜, 그리고 兪의 月을 보류한 揄·癒·諭·愉와 같은 기준으로 보류했다.
보류 2자는 `next-batch.json` 후보에서 뺀다.

같은 회차의 肢·腫·膣처럼 사전도 月 안을 가로 둘로 쓰는 글자와,
叱처럼 匕를 사전과 같은 삐침·갈고리 순서로 쓰는 글자는 그대로 뒀다.

부수 유사성으로 승인하지 않았다. 각 글자의 사전 전체 필순을 순서대로 보고,
색으로 나눈 25% 진행 구간에서 방향·펜 떼기·획 경계·완성 자형을 대조했다.
보정 7자는 변경 획뿐 아니라 전체 획을 재대조했다.

[direction-probe.mjs](direction-probe.mjs)가 60°를 넘는 획 19개(9자)를 표시했고,
7자는 보정으로, 嗔·朕 2자는 보류로 이어졌다. 표시만 되고 그대로 둔 획은 없다.
踵·腫·櫛·嗟·蹉처럼 덩어리로 얽힌 자리는 획 끝점 좌표를 숫자로 확인한 뒤 대응을 맞췄다.
45~60° 구간의 방향 차이는 13개였다. 모두 사전이 세로로 긋고 허가 원본이 기울여 쓰는 짧은 점(猝·廚·註·竣·疹·膣·嫉·搾·窄)과
糸·火의 짧은 획(踪·紂·紬·櫛)으로, 이전 회차와 같은 기준으로 임계 아래는 허가된 중간선을 그대로 뒀다.
이번 회차 원문에는 가로 이동 변환이 없었다.

## 근거와 재현

- [observations.json](observations.json): 50자 판정, 7자의 첫 판정·보정·재대조 기록, 2자의 보류 사유, 8방향 코드
- [source-checks.json](source-checks.json): 50자의 원문 해시·획별 시간·XML 참조·좌표 변환
- [originals.json](originals.json): 고정한 라이선스 원본의 중간선과 정규화 경로
- [proposals.json](proposals.json), [corrections.json](corrections.json): 획별 원본 대응과 국소 보정 이유

- [prepare.mjs](prepare.mjs): 읽기 전용 승인 데이터 재현 (48자 승인·2자 보류를 검사)
- [verify.mjs](verify.mjs): 재현 결과·공개 데이터·적용 수·다음 후보 검증. 1급 회차의 보류 글자는 큐에서 뺀다
- [checks.json](checks.json), [progress.json](progress.json): 이번 검증과 전체 진행 현황
- [next-batch.json](next-batch.json): 다음 篡~稍 50자·708획 후보
- [acquire.mjs](acquire.mjs), [source-checks.mjs](source-checks.mjs), [serve.py](serve.py): 원본 고정·원문 확인·검토 시트

필순 근거는 e-hanja 사전이며, **한국어문회 인증으로 표시하지 않는다.**
재생 중간선은 Arphic Public License의 고정 MM·Ja 원본에서 출발했다.
사전의 경로·마스크·영상·스크린샷을 파일에 저장하거나 배포하지 않았다.
자형의 구조와 진행 방향을 비교한 것으로 폰트 외곽선의 픽셀 일치나 필기 채점이 아니다.
