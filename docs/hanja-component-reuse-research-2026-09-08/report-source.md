# 기존 부품으로 한자 획 애니메이션을 확장할 수 있는가

- 작성일: 2026-09-08
- 대상: lingo 한능검 트랙의 개발·콘텐츠 의사결정
- 범위: 현재 승인된 743자의 경로를 재사용하여 미적용 5,235자의 후보를 자체 생성할 수 있는지 조사
- 결론: 조건부 가능. 위치별 부품과 전체 필순을 관리하는 합성기를 권장한다.
- 이번 결과: 조사, 정량 후보 분석, 연구용 합성 예시 2개. 앱 데이터·승인 원장 변경 없음.
- 근거 수준: 국내 교과서·공식 상담 / 표준·원본 데이터 / 연구 논문 / 현재 저장소 분석 / 명시된 설계 제안
- 아직 하지 않은 검증: 전체 후보의 한국 필순 판정, 위치별 부품 추출, 홀드아웃 성능 평가, 새 후보의 앱 적용

## 1. 판단

검증된 부품의 획 경로를 재사용해 새 글자의 애니메이션 후보를 만드는 방식은 타당하다. 개별 글자를 매번 새로 그리는 비용을 줄일 수 있고, 같은 부품을 한 번 보정하면 여러 글자에 반영할 수 있다. 단, 사전 분류용 부수 하나만으로 글자 전체를 조립할 수는 없다. 구성요소 전체, 위치에 따른 자형, 글자 전체의 재생 순서가 필요하다.

모든 목표 글자에 개별 공식 영상이 있어야만 후보를 만들 수 있다는 정책으로 제한할 필요는 없다. 이미 확인한 부품과 국내 필순 규칙을 근거로 자체 합성하고, 전체 글자를 검토한 뒤 별도의 자체 검토 등급으로 운영하는 방식을 제안한다. 부품의 공식 근거가 새 글자의 공식 검증을 자동으로 보증하지는 않는다.

국내 교과서는 부수의 사전적 기능과 위치별 변형을 구별한다. [미래엔: 고등학교 한문Ⅰ 교사용 지도서](http://textbook-miraen.cdn.x-cdn.com/textbook/newbook/high/chinese/%EA%B3%A0_%ED%95%9C%EB%AC%B8%E2%85%A0_%EC%A7%80%EB%8F%84%EC%84%9C_%EC%96%91%EB%A9%B4.pdf) 31쪽. Unicode도 구성요소와 부수 변형을 설명하지만 IDS는 공간 구조를 기술한다. 필순을 제공하는 명세가 아니다. [Unicode Consortium: The Unicode Standard 17.0, Chapter 18, §18.1.14 and §18.2](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-18/)

## 2. 현재 데이터에서 재현한 후보 수

전체 5,978자 중 승인된 획 애니메이션은 743자(어문회 503 + 교과서 240), 미적용은 5,235자다. 현재 파일을 직접 읽어 확인했다. 이 수치는 배포 상태를 재확인한 것이 아니라 작업 트리 기준이다.

고정한 Make Me a Hanzi 사전의 IDS 분해를 현재 승인 글자와 대조했다. [skishore / Make Me a Hanzi contributors: Make Me a Hanzi — README and dictionary.txt](https://github.com/skishore/makemeahanzi/blob/bddc96d41bef78427ed0e034e9f7e31d71fd1b92/README.md)는 구조 후보 탐색 자료이며 한국 필순의 검증 자료가 아니다.

| 단계 | 수 |
|---|---:|
| 미적용 글자 | 5,235 |
| 사전에 동일 코드 포인트 존재 | 4,052 |
| 복합 IDS 존재 | 4,037 |
| 직접 IDS에 미상 기호 없음 | 3,892 |
| 직접 구성요소가 모두 승인된 독립 글자 | 502 |
| 중간 구성요소를 재귀 분해해 모두 승인된 독립 글자로 도달 | 669 |

재귀 후보 669자는 미적용 글자의 12.8%다. 이 값은 자동 적용 가능 수나 방식 전체의 최대치가 아니다. 실제로는 승인된 복합 글자에서 氵·忄 같은 부품을 추출하면 후보가 늘 수 있고, 한국 자형·획수·순서가 맞지 않아 탈락할 수도 있다.

|---|---:|---:|---:|
| 4급II | 9 | 2 | 22.2% |
| 4급 | 250 | 40 | 16.0% |
| 3급II | 499 | 70 | 14.0% |
| 3급 | 317 | 47 | 14.8% |
| 2급 | 538 | 87 | 16.2% |
| 1급 | 1,144 | 176 | 15.4% |

분류는 각 글자의 최초 배정 급수 기준이며 누적 급수표가 아니다. 8급부터 5급까지는 미적용 글자가 없어 표에서 생략했다.

669자 중 외부 사전의 획-구성요소 매칭이 유효하고, 원본 승인 부품의 획수 합과 외부 목표 글자의 획수가 각각 우리 카탈로그와 일치하는 교집합은 609자다. 각 개별 조건은 매칭 644, 부품 합 632, 외부 목표 획수 639자다. 서로 독립된 검사이므로 수치를 순서대로 차감해서 읽으면 안 된다. 이 검사들은 구조적 모순을 걸러내며 한국 필순·자형이 맞다는 정답 판정은 하지 못한다.

매칭 유효성은 목표 및 재귀 확장한 미승인 중간 글자의 모든 matches가 non-null이고 해당 IDS 트리의 유효한 노드에 도달하는지 확인했다. 말단 leaf 도달은 강제하지 않고 승인 원본 글자에서 재귀 검사를 멈춘다. 반복 부품은 출현 횟수만큼 획수를 더한다. 실제 원본 획과 목표 획의 일대일 대응·중복·누락, 중간 글자별 획수 일치, 부품 사이 획 공유는 검사하지 않았다. 그러므로 609는 경로 합성의 정확성 검증 수가 아니다.

방법: 동일 코드 포인트만 사용하고 자동 정규화·이체자 치환은 하지 않았다. 승인 743자를 종료점으로 삼아 IDS 연산자를 파싱하고, 미승인 중간 글자는 사전에서 재귀 확장했다. 알 수 없는 기호, 누락·해결 불가능한 분해는 제외했다. 연구 에이전트의 계산을 조정 에이전트가 별도 고정점 계산으로 재현해 직접 502 / 재귀 669를 확인했다. 획 경로 자체를 목표 글자의 공식 필순과 비교한 실험은 아니다.

사전 9,574행, 2,570,140바이트. commit `bddc96d41bef78427ed0e034e9f7e31d71fd1b92`; SHA-256 `744bb05d5b0742e9ee35c37791f94d56a173349b3367569e7ca11e510364d203`. 미적용 중 사전 부재 1,183, 복합 분해 없음 15, 직접 미상 포함 145, 후손 부품 해결 불가 3,223, 후보 669로 총 5,235다. 사전 부재는 공식 자료 부재를 뜻하지 않는다.

## 3. 실제로 재사용할 수 있는 것

`砲 = 石 + 包`, `豊 = 曲 + 豆`, `略 = 田 + 各`, `粉 = 米 + 分`, `智 = 知 + 日`은 고정한 IDS에서 확인했으며 각 구성 글자의 승인 애니메이션이 현재 존재한다.

보고서의 砲(10획), 豊(13획)는 이 중 두 조합을 그대로 합성한 연구 예시다. 원본 경로를 보고서용으로 직접 정한 사각 영역에 이동·비등방 확대/축소했다. 목표 글자의 위치 추정, 접합 보정 또는 한국 전체 필순 검증은 하지 않았다. 미검증이며 앱에 적용하지 않았다. 豊는 기존 교과서 자료가 豐(18획)인 문제 때문에 보류된 글자로, 曲+豆의 합성이 그 자료 불일치를 해결하거나 공식 승인을 대신하지 않는다.

현재 교과서 보정 레시피는 94개이며 그중 23개는 총 획수가 달라진다. 城·盛·誠의 成 분할, 警·權·護·蓄의 풀초두, 送·造·退·達·導·逆의 받침 보정은 동일 계열의 수정이 반복된 실제 사례다. 이것은 공통 부품 레시피로 관리할 가치가 있음을 보여 준다. 이미 보정 대상으로 고른 집합이므로 94/240을 전체 한자의 오류 발생률로 해석하면 안 된다.

| 문제 | 확인 사례 | 합성기 조건 |

| 나중에 그리는 부분 | 途의 받침, 犬의 오른쪽 위 점, 中의 관통획 | 지연·마감 규칙 |

## 5. 권장 구현

현재 플레이어는 순서가 있는 SVG paths를 재생하므로 새 애니메이션 라이브러리는 필요 없다. 생성·검증 데이터를 별도로 설계하면 된다.

1. **위치별 부품 원장**: 부품의 실제 모양·위치·변형, 승인 원본 글자, 원본 획 인덱스 목록, 출처와 해시를 기록한다. 부품 획은 연속 구간이라고 가정하지 않는다.
2. **분해·배치 레시피**: IDS로 후보를 얻고 한국 코드 포인트와 모양을 확인한다. 목표 Noto KR SVG는 배치·여백의 시각 기준으로 쓴다. 완성 외곽선은 필순의 증거가 아니다.
3. **획 일정**: (부품 인스턴스, 내부 획 번호)의 전체 목록이나 선후 제약으로 안쪽·마감·지연획을 표현한다. 같은 부품의 내부 순서와 글자 전체의 순서를 분리한다.
4. **경로 생성**: 먼저 이동·축소/확대로 조합하고 필요한 끝점·접합은 명시적 보정 레시피로 수정한다. 현재 앱과 같은 100 단위 좌표계·둥근 5 단위 획으로 검사한다.
5. **독립적인 전체 검토**: 획수, 끊는 위치, 방향, 전체 순서, 접합, 한국 자형을 확인한다. 공식 목표 영상이 없으면 확인된 부품과 적용 규칙, 자체 판단 부분을 함께 기록한다.
6. **출처 등급 분리**: 현재의 개별 어문회·교과서 대조 자료를 유지하고, 새 후보에는 합성 초안 및 자체 검토 합성이라는 별도 상태를 둔다. 전체 검토 없이 공식 검증 상태로 자동 승격하지 않는다.

유한 좌표·경계·중복/누락·매핑·획수·해시 검사로 생성기의 오류를 줄일 수 있다. 이 자동 검사만으로 언어적 정답을 증명할 수는 없다. LLM은 분해와 예외 탐색을 돕고, 경로 조립은 재현 가능한 코드로 수행하는 편이 적합하다.

## 6. 학습 모델부터 만들 필요는 없다

LF-Font는 구성요소의 국소 표현을 재사용하면서도 전체 구조 인코더가 필요함을 보여 준다. 소수 참조 예시라는 표현은 큰 사전학습을 전제로 하며, 743개 경로만으로 한국 필순을 바로 학습한다는 뜻이 아니다. [AAAI 2021: Few-shot Font Generation with Localized Style Representations and Factorization](https://ojs.aaai.org/index.php/AAAI/article/view/16340)

획 등록 연구는 이미 획이 있는 참조를 목표 모양에 맞추는 방법을 제공한다. 교차가 많거나 국소 구조가 크게 다르면 실패하며, 정답 필순이 없는 글자에서 순서를 새로 증명하는 기술이 아니다. [AAAI 2023: Stroke Extraction of Chinese Character Based on Deep Structure Deformable Image Registration](https://ojs.aaai.org/index.php/AAAI/article/view/25220)

따라서 첫 단계는 규칙 기반 합성과 위치별 부품 관리다. 이후 실제로 반복되는 모양 보정에 한해 등록·변형 모델의 효과를 평가한다. 외부 dictionary와 graphics는 각각 LGPL 3+와 Arphic Public License로 구분되므로 도입할 데이터와 배포 조건을 분리해서 확인한다. [Make Me a Hanzi contributors: Make Me a Hanzi COPYING](https://github.com/skishore/makemeahanzi/blob/bddc96d41bef78427ed0e034e9f7e31d71fd1b92/COPYING)

## 7. 다음 단계 제안

**승인된 100자의 재구성 평가 + 미적용 20자의 시범 제작**을 권장한다. 이는 계획이며 이번에 평가하거나 새로 승인한 수가 아니다.

먼저 좌우·상하·둘러싸기·변형 부품을 포함한 승인 글자 100자를 평가 전용으로 분리한다. 해당 목표의 원본 획 경로·정답 레시피가 부품 추출이나 생성에 유출되지 않게 하고, 나머지 원본에서 부품을 추출한다. 이미 본 위치의 부품과 새로운 변형을 구분해 평가한다. 목표 Noto 외곽선은 모양 기준으로 사용할 수 있으나 목표의 순서 있는 획 경로를 재사용하는 것과 구별한다.

그다음 609자 구조 후보에서 좌우·상하의 저위험 조합 20자를 골라 생성·검토한다. 砲·略·粉·智 같은 구조를 우선 검토하고, 豊/豐 같은 이체 문제와 복잡한 둘러싸기·획 연결은 별도 처리한다.

측정: 글자 단위 전체 필순 일치, 허용 변형, 획 방향·분할, 자형·접합, 보류 비율, 사람이 고치는 시간. 이미지 겹침 비율만으로 평가하지 않는다. 표본에서 오류가 없더라도 나머지 5,235자 전체의 무오류를 주장하지 않는다.
