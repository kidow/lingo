# 가나 탭 설계

상태: 청음 91장 구현 · 탁음·요음은 미공개 · 갱신일: 2026-09-13

JLPT 트랙 안에 히라가나·가타카나를 배우는 덱을 하나 더 둔다. 개념(낱말)이
아니라 **글자**를 카드로 세우는 자리라 한능검(`docs/hanja-track-design.md`)과
구조가 가장 가깝다. 다만 한능검은 트랙이고 가나는 **덱**이다 — JLPT 안에
있어야 하기 때문이다.

이 문서는 결정과 그 이유를 적는다. 수치는 전부 실측이다.

## 1. 카드의 단위

- **글자 하나가 카드 하나다.** `あ` 카드와 `ア` 카드가 따로 선다.
- 히라가나와 가타카나를 **덱으로 가르지 않는다.** 한 덱에 섞여 나오고,
  어느 쪽인지는 카드의 라벨이 말한다. 요구 그대로다 — 구별해 학습하지
  않되 표시는 한다.
- 소리 하나에 카드 하나(`あ/ア`를 한 장에)로 두지 않는 이유는 **예시 낱말**이다.
  `あ`의 예시(`あめ`·`あり`·`あな`)와 `ア`의 예시(`アヒル`·`アイマスク`·`アンケート`)는
  겹치는 데가 없다. 한 장에 담으면 낱말 여섯이 붙어 카드가 터진다.

### 마디

「글자 하나」가 아니라 **가나 한 마디**가 정확한 말이다. `きゃ`는 두 글자지만
소리 하나이고, 학습자가 외우는 단위도 그쪽이다.

| 갈래 | 마디 | 카드 |
|---|---:|---:|
| 청음 | 46 | 91 |
| 탁음·반탁음 | 25 | 50 |
| 요음 | 33 | 66 |
| **합** | **104** | **207** |

- 가타카나 확장음(`ファ` `ティ` `ウィ` `ヴ` `ジェ` …)은 **넣지 않는다.** 가나가
  아니라 표기 관습이다 — `フ`를 아는 사람은 `ファ`를 읽는다. 넣으면 104:124로
  좌우가 어긋나 「같은 소리의 두 표기」라는 구조가 깨진다.
- `ヲ`는 **뺀다.** 가타카나 조사인데 현대 일본어에서 조사는 히라가나로만 쓴다.
  낱말도 구절도 실물이 없어 예시 세 개를 영영 못 채운다. 그래서 히라가나 104,
  가타카나 103, 합 207이다. `を` 카드의 상대 표기 줄은 「가타카나 표기는 쓰지
  않는다」로 대신한다.
- 요음이 들어오므로 탁음·반탁음은 **자동으로 딸려 온다** — `ぎゃ` `じゃ` `びゃ`
  `ぴゃ`가 그 위에 선다.

## 2. 예시 낱말

각 카드에 예시 낱말 **셋**과 그 발음을 붙인다. 글자 자체의 발음 파일은 두지
않는다.

### 기존 개념을 참조한다

예시는 새로 적지 않고 `content/*.json`의 **개념 slug를 가리킨다**.

```json
"hira": { "glyph": "あ", "examples": ["rain", "ant", "hole"] }
```

- 낱말·읽기·뜻·mp3·그림이 전부 개념에서 따라온다. `SayButton`은 slug와 lang만
  받으므로 `<SayButton slug="rain" lang="ja" />` 그대로 쓴다 — 새 컴포넌트가
  필요 없다.
- 새로 적으면 같은 낱말이 두 벌로 갈린다. `rain`의 읽기가 바뀔 때 한쪽만
  고쳐지고 아무도 모른다 — `pnpm dup`가 감시하는 것이 그 사고다.

**실측:** 일본어 읽기와 mp3가 둘 다 있는 개념이 4,736개다. 「그 마디를 포함」
기준으로 히라가나 104마디 중 91, 가타카나 104 중 78이 이미 셋을 채운다.

### 고르는 규칙

스크립트가 초안을 뽑고 **사람이 시트를 눈으로 본다.** 자동 규칙은 `あ` 카드에
`あんないばん`(길 표지판)을 앉힌다 — 실제 후보 목록 맨 위에 그것이 있었다.

우선순위:

1. mp3가 있는 개념만 (없으면 후보가 아니다)
2. 그 마디로 **시작**하는 것 우선, 모자라면 **포함**하는 것
3. **짧은 것 우선** (모라 수 오름차순)
4. 낱말(`noun`·`verb`·`adjective`) 우선, 모자랄 때만 통짜 표현(`scene`)
5. 그림이 있는 것 우선

**시트를 보고 규칙 둘을 더 넣었다.** 자동 초안이 실제로 저지른 것들이다.

- **그 마디보다 긴 낱말만.** `し` 후보 맨 위가 `し`(죽음)와 `し`(시)였다.
  배우는 글자가 그대로 예시가 되면 아무것도 안 가르친다.
- **조각으로만 든 낱말은 뺀다.** `し`에 `しゅと`(수도)가, `い`에 `いしゃ`(의사)가
  붙었다 — 글자는 거기 있지만 소리는 `しゅ`·`しゃ`라 배우는 것과 다르다.
  가타카나 확장음도 같은 규칙에 걸린다(`ツ`에 붙은 `ツァーリ`).
- **앞머리가 겹치면 뒤로 미룬다.** `ヘ` 예시가 `ヘアゴム`·`ヘアネット`·`ヘアピン`
  셋이었다 — 글자는 맞지만 한 낱말을 세 번 보는 것과 같다.

통짜 표현을 허용하므로 `を`가 산다 — 「みずを ください」가 예시가 된다.

**한 낱말은 최대 두 장까지.** 완전히 막으면 희귀 마디에서 후보가 마르고,
무제한이면 같은 그림이 카드마다 반복돼 피드가 지겨워진다.

## 3. 데이터

**도표는 코드에, 예시는 콘텐츠에.** 글자·로마자·행·갈래는 고르는 것이 아니라
정해진 것이라 `lib/kana.ts`의 `KANA_TABLE`에 있다. 사람이 고르는 것은 예시
낱말뿐이고 그것만 `content/kana.json`에 있다.

```jsonc
// content/kana.json — 마디 id → 표기별 개념 slug 셋
{ "a": { "hira": ["ant", "autumn", "older-brother"],
         "kata": ["duck", "album", "antenna"] } }
```

가타카나 글자는 **히라가나에서 유도한다**(코드포인트 +0x60). 두 벌을 손으로
적으면 한쪽만 고쳐지는 날이 온다. `を`만 `kata: null`이다.

카드 207장은 `kanaEntries()`가 104마디를 두 표기 × 두 능력으로 펼쳐 만든다 —
`lib/hanja.ts`의 `HANJA_SKILLS.map`과 같은 자리다. 짝은 도표가 들고 있으므로
소개 카드가 상대 표기를 적을 때 `id` 문자열 규칙에 기대지 않는다.

### `id`와 `romaji`를 가른다

로마자를 그대로 `id`로 쓰면 충돌이 셋 난다. `id`는 고유 키, `romaji`는 화면에
보일 글자다.

| 마디 | `id` | `romaji` |
|---|---|---|
| お | `o` | `o` |
| を | `wo` | `o (を·조사)` |
| じ | `ji` | `ji` |
| ぢ | `dji` | `ji (ぢ)` |
| ず | `zu` | `zu` |
| づ | `dzu` | `zu (づ)` |

### 어디에 싣나

`ja` 코퍼스 안에 `kana` 필드를 하나 더 단다 —
`Corpus = { concepts, trivia, articles, kana }`.

예시가 slug 참조라 **개념 목록과 같은 파일에 있어야 조회가 공짜다.** 따로 받으면
`KanaFeed`가 코퍼스를 기다린 뒤 또 하나를 기다린다. 가나는 일본어에만 있으므로
다른 트랙은 애초에 받지 않는다. 크기는 참조 배열뿐이라 20KB 안팎이다.

## 4. 출제

### 무엇을 묻나

소개 + **양방향 4지선다** 둘이다. 한능검의 `recognition`/`hun-eum` 구조를 그대로
옮긴다.

- `글자 → 소리` — `あ`를 보고 `a`를 고른다
- `소리 → 글자` — `a`를 보고 `あ`를 고른다

읽기와 쓰기가 다른 능력이다. 한 방향만 하면 읽을 수는 있어도 `さ`를 쓰지 못한다.

**듣기 문항은 두지 않는다.** 예시 낱말 mp3는 낱말 전체의 소리라 「이 소리에 어느
글자가 들었나」는 가나 문제가 아니라 청해 문제가 된다.

소리는 **헵번식 로마자**로 적는다. `romanization` 필드가 이미 그 방식이고, 한글
표기(`츠`/`쓰`)는 사람마다 갈려 정답을 못 정한다.

### 오답 후보

`lib/confusables.ts`는 207마디 중 **45만 덮는다**(빈칸 카드용으로 손으로 적은
것이라 그렇다. 요음은 하나도 없다). 그래서 사다리로 뽑는다.

1. 혼동표 (`シ/ツ`, `ね/れ/わ` — 규칙이 못 잡는 진짜 혼동)
2. 같은 행 (자음이 같다: `か き く け こ`)
3. 같은 단 (모음이 같다: `あ か さ た な`)
4. 무작위

- **탁음 짝을 오답에 넣는다.** `が`의 오답에 `か`가 서면 점 유무를 훈련한다.
- **문자 종류는 섞지 않는다.** `あ` 문제의 오답은 히라가나만. 섞으면 표기를
  고르는 문제가 되어 「구별하지 않는다」는 원칙과 어긋난다.
- `소리 → 글자`에서 `o`·`ji`·`zu` 충돌 짝이 한 화면에 서지 않게 한다. 서야 할
  때는 `romaji`의 구별 표시가 정답을 하나로 만든다.

### 순서

**무작위다.** 새 카드 순서를 따로 정하지 않는다 — 기존 `Feed`가 `ordered`를
켜지 않았을 때 하는 일 그대로다. 추가 코드가 없다.

### 진도

- 키 `kana:{script}:{id}:{skill}` — `kana:hira:a:read`, `kana:kata:kya:write`
- `KANA_LADDER = { min: RUNG_CHOICE, max: RUNG_CHOICE }` (한능검과 같다)
- 소개 카드는 **글자마다 한 번**, 능력마다 두 번이 아니다
- 숙련도 분모는 **가나 안에서만** 센다. `상식`이 이미 그렇다 — 세는 단위가
  다르면 한 줄에 못 합친다 (`lib/deck.ts`)

## 5. 화면

### 덱으로 얹는다

`DeckId`에 `'kana'`를 더한다. `Shell`이 `shownDeck === 'kana'`일 때 `KanaFeed`를
세운다.

- 트랙을 옮기면 저장된 `kana`가 저절로 무효가 된다 —
  `decks.includes(deck) ? deck : DEFAULT_DECK`이 이미 그 일을 한다
- 탭은 JLPT에서만 선다. 트랙 이름을 묻지 않는다 — 가나 데이터가 `ja` 코퍼스에만
  실리므로(`scripts/split.ts`) 다른 트랙에서는 `kana`가 빈 배열이고, 탭 목록은
  이미 「비면 안 세운다」로 돌아간다. 표현·상식 탭과 같은 규칙이다

가나를 `Concept`으로 위장해 기존 `Feed`에 태우지 않는다. `Concept`은 slug·그림·
일곱 언어를 전제하는데 가나는 그중 아무것도 없고, `Shell`이 `undrawn`으로 그림
없는 개념을 거르므로 207장이 통째로 사라진다.

### 탭

`가나 | 단어 | 표현 | 상식` — **맨 앞**이다. 문자를 모르면 단어 카드를 못
읽으므로 탭 순서가 그대로 학습 순서가 된다. 기본 덱은 `word` 그대로라 처음 여는
화면이 가나가 되지는 않는다.

이름은 `가나`다. 나머지가 전부 한국어 두 글자라 `かな`만 일본어면 줄이 깨진다.

### 소개 카드

그림 자리에 **배우는 글자 하나만** 크게 세운다. 상대 표기(`ア`)는 시트의 메타
줄에 작게 적는다.

두 글자를 나란히 크게 두지 않는 이유 — `ア` 카드가 따로 서므로, `あ` 카드에
`ア`를 크게 세우면 방금 본 것을 또 본 줄 알고 넘긴다. 207장에서 이 착시가 매번
난다.

예시 셋은 **썸네일 + 낱말 + 뜻·로마자 + 재생 버튼** 한 줄씩이다. 그림 3칸
그리드로 두면 44px 재생 버튼이 안 들어가 낱말 자체를 눌러야 하는데, 그 동작은
넘기기와 부딪힌다.

### 찾기

`Hit`에 `kana`가 넷째로 붙되 **정확 일치일 때만, 맨 위 한 줄**이다. `あ`·`きゃ`·
`ka`처럼 마디 자체를 쳤을 때만 선다.

일반 결과에 섞으면 찾기가 망가진다 — `あ`는 일본어 낱말 수백 개에 들어 있는
글자다. 그렇다고 빼면 **「이 글자 뭐였지」**라는 가장 흔한 물음에 답할 데가
없다. 한국어 자모 검색은 붙이지 않는다 — 가나에는 한국어 제목이 없다.

## 6. 헤더 폭

탭이 하나 늘면 넘친다. 실측이다.

| 조각 | 폭 |
|---|---:|
| 탭 버튼 하나 | **46px** — `min-w-11`(44)이 아니라 `px-2.5`(20) + 글자(26)가 정한다 |
| 버튼 5개 (단어·표현·상식·가나·찾기) | 230px |
| 구분선 4개 | 12px |
| 트랙 이름 + 국기 + 화살표 + 숙련도 + 간격 | 114px |
| 헤더 좌우 패딩 | 40px |
| **합** | **397px** |

390px에서도 9px 넘친다. 320px에서는 탭 다섯이 물리적으로 불가능하다 —
패딩과 트랙 이름을 빼면 194px만 남는데 44px짜리 다섯은 220px이다.

그래서 **찾기를 헤더에서 빼 FAB로 내린다.** 헤더가 348px이 되어 320px에서도
탭 넷이 선다. 탭 간격과 구분선은 그대로 둔다.

- **전 트랙에 적용한다.** JLPT만 FAB로 두면 같은 기능이 트랙마다 다른 자리에
  있게 된다 — `header.tsx`가 「찾기는 언제나 선다」고 적어 둔 것이 막으려던
  상태 그대로다.
- 우측 하단이다. `brand-spec.md`의 「엄지 사정권에 탭 대상을 두지 않는다」는
  하단 **탭바**(가로로 늘어선 여러 개)를 두고 쓴 문장이라, 단일 FAB를 예외로
  좁혀 다시 썼다.
- `Retry`·`Skeleton` 상태에서는 세우지 않는다. 검색할 콘텐츠가 없다.

## 7. 검사

`pnpm check`가 막는 것:

1. 예시 slug가 실존하는 개념이고 `words.ja`가 있는가
2. 예시 낱말의 읽기에 그 마디가 실제로 들어 있는가 (오배정)
3. 그 개념의 mp3가 있는가 (`AUDIO_MISSING` 대조)
4. **공개한 갈래의 모든 마디**가 예시 셋을 채웠는가
5. 한 낱말이 세 장 이상에 겹치지 않는가
6. `id`가 고유한가
7. `소리 → 글자` 문항에서 정답이 둘이 되지 않는가

눈으로 보는 것 — **시트 한 장**(`scripts/sheet.ts` 선례). 자동 검사가 못 잡는
것이 거기서만 잡힌다: 어색한 낱말(`あざらし`), 초급이 모를 낱말, 그림과 뜻의
어긋남.

## 8. 공개 순서

**갈래 단위로 끊는다.** 카드 단위로 준비되는 대로 열면 `さ`는 있는데 `し`가 없는
화면이 된다. 낱말 피드에서는 개념 하나가 비어도 아무도 모르지만(`undrawn` 열일곱이
그렇게 빠져 있다) 가나는 **빠진 자리가 보인다** — 학습자가 오십음도를 머릿속에
갖고 오기 때문이다.

부족분은 **새로 만들 mp3 수**다.

| 회차 | 갈래 | 카드 | 부족한 마디 | 새 mp3 |
|---|---|---:|---|---:|
| ② | 청음 | 91 | `ヌ`(2) — 예외로 적고 세움 | 0개 |
| ③ | 탁음·반탁음 | 50 | `ぢ`(0) `ぺ`(2) `ゾ`(1) `ヂ`(0) `ヅ`(0) | 11개 |

### `ヌ`는 예시가 둘이다

`ヌ`를 품은 개념이 콘텐츠 전체에 `カヌー`·`スヌーズ` **둘뿐이다.** 셋째를
만들려면 개념을 새로 넣어야 하는데(그림과 발음까지), 그 하나 때문에 청음
91장이 통째로 묶이는 편이 더 나쁘다.

그래서 `lib/kana.ts`의 `EXAMPLE_SHORT`에 **적어 두고** 세운다.
`lib/audio-have.ts`가 없는 것만 적어 두는 것과 같은 규칙이다 — 예외가
목록에 있으면 다음 사람이 채울 자리를 안다. `pnpm check`도 이 목록을 보고
센다.

채우려면 `ヌ`가 든 개념을 하나 넣고(`ヌードル`·`ヌンチャク` 따위) 예외 줄을
지우면 된다.
