# 한능검 트랙 설계

상태: 전 15급수 5,978자 적용 · 갱신일: 2026-09-06

기준 시험: 한국어문회 전국한자능력검정시험. 자격명은 한자능력급수다.
이 문서는 한능검의 제품 동작, 데이터, 기존 코드와의 연결 지점, 검증 조건을 정의한다. 현재 구현은 전 급수의 한자·훈음 학습과 공식 도해로 검증한 49자의 필순 재생이다. 모든 시험 문항 유형이나 손글씨 정확도 검증이 완료되었다는 의미는 아니다. 나머지 필순·획 판정·쓰기 배정 설계는 후속 범위다.

현재 구현은 **8급부터 특급까지 15급수, 중복 없는 5,978자**다. 소개, 한자 선택, 훈음 4지선다, 검색, 자유 쓰기 캔버스를 제공한다. 급수 선택·탭·음성은 없으며 각 글자에 최초 읽기 배정 급수를 표시한다. 한자어는 기존 예시 10자의 카드 안에서만 제공한다. 숙련도는 한자 선택과 훈음 선택을 각각 기존 FSRS로 기록하고 두 능력이 모두 숙련된 글자 수 / 5,978자로 계산한다. 기존 10자의 진도 키는 유지한다.

쓰기 연습은 아이콘으로 취소·지우기하고 흐릿한 정답 SVG를 기본으로 겹쳐 보는 방식이다. 모든 한자의 기본 표시는 Noto Serif CJK KR 원본에서 추출한 로컬 SVG를 사용한다. **공식 필순 도해와 대조한 49자만 필순을 재생한다.** 활성 소개 카드와 쓰기 연습 진입 시 한 번 자동 재생하고, 다시 재생 아이콘으로 처음부터 반복할 수 있다. 쓰기 기준 SVG는 재생 중에도 유지하며, 반복 재생은 필기 내용을 지우지 않는다. 검색 상세는 버튼으로 재생을 시작한다. 동작 줄이기 설정에서는 자동 재생하지 않고 클릭마다 한 획씩 표시한다. 화면 밖 카드와 숨겨진 탭은 자동 재생하지 않는다. 미검증 글자는 정적 SVG만 표시한다. 자동 채점은 제공하지 않는다. 글자별 근거와 구현 범위는 [필순 출처 조사](hanja-stroke-sources.md#현재-적용한-49자)와 [SVG 표시 기록](hanja-svg-feasibility.md)에 기록한다.

2026-09-07 자동 재생 검증: 타입 검사·테스트 144개 통과. 브라우저에서 校 소개의 자동 1/10 시작, 다음 敎 카드의 0/11 대기, 山·校 쓰기 진입 시 SVG 가이드와 자동 재생, 다시 재생 시 1획 필기 보존을 확인했다. 동작 줄이기 설정을 읽기 전에는 자동 재생하지 않도록 구현했다.

구현: `content/hanja/characters/*.json`, `lib/hanja-corpus.ts`, `lib/hanja.ts`, `lib/hanja-strokes.ts`, `components/hanja/`. 공식 전체 XLS의 5,978개 항목과 15개 급수별 HWP의 누적 문자 집합을 대조했으며 원문 SHA-256과 확인일을 데이터에 남겼다. 검증: 타입 검사와 139개 테스트 통과. 모든 글자의 양방향 4지선다 11,956개 생성, 기존 진도 키 유지, 급수별 검색, 필순 허용 목록·총획·재생 시간을 검증한다. 데이터 변환 규칙·급수별 수량·검증 명령은 [한자 데이터 출처](hanja-data-sources.md)에 기록한다.

## 1. 설계 결정

- 트랙 ID는 `hanja`, 화면 이름은 `한능검 🇰🇷`, 설명은 `한국어문회 기준`으로 한다.
- 전체 15급수는 콘텐츠 메타데이터로 모델링한다. 초기에는 목표 급수 선택을 제공하지 않고, 각 한자에 최초 읽기 배정 급수를 표시한다.
- 다른 트랙과 같은 진입·학습 흐름을 유지한다. 급수·누적/신규 범위 필터는 후속 기능으로 미루며, 같은 한자의 진도를 급수별로 복제하지 않는다.
- 기본 학습은 한자와 훈음·독음이다. 이미지·음성·외국어 예문을 필수로 요구하지 않는다.
- 음성 버튼·자동재생·듣기 문항은 제공하지 않는다. 훈음·독음·장단음이라는 학습 내용은 별개다.
- 한자 선택, 훈음 4지선다, 쓰기 연습을 구분한다. 한자어는 한자 카드의 활용 예시로 제공하며 별도 탭·독음 퀴즈·진도는 두지 않는다. 선택 정답을 쓰기 숙련도로 인정하지 않는다.
- 현재 쓰기는 자유 입력과 정답 글자 겹쳐 보기다. 획 비교와 시험 답안 자동 채점은 제공하지 않는다.
- 전 15급수의 읽기 배정 한자를 같은 피드에 제공한다. 부수·성어·한문 등 별도 문항 유형은 후속 범위다.
- 기존 세로 피드와 복습 방식을 유지한다. 모의고사·시간 제한·합격 예측은 이 설계의 구현 범위에 포함하지 않는다.

### 배정 정보와 후속 범위 선택

- 초기 학습 대상은 공개·검수가 끝난 한자 전체다. 사용자는 급수를 선택하지 않는다.
- 후속 범위 필터를 도입할 때 `누적 전체`는 선택 급수의 읽기 배정 집합, `새로 추가된 한자`는 직전 단계의 집합을 뺀 결과로 정의한다. 현재 출시 범위에는 두 필터 모두 포함하지 않는다.
- 예: 7급 전체는 150자, 새로 추가된 한자는 7급Ⅱ의 100자를 제외한 50자다.
- 후속 필터의 한자어 적용은 별도 출제 범위를 검수한 뒤 결정한다. 쓰기 배정 집합은 읽기 집합과 별도로 관리한다.
- 쓰기 집합을 단순히 “두 급수 아래”로 계산하지 않는다. 특히 1급 쓰기 2,005자는 별도 명단 대조가 필요하다.
- 최초 읽기 배정 급수와 공식 집합의 포함 관계를 검증한다. 예외가 발견되면 공식 명단을 우선하고 원자료 오류·판본 차이를 조사한다.

### 공개 상태

검수된 항목부터 공개한다. 화면의 학습 수량은 실제 공개된 한자 수이며 공식 급수의 전체 수량과 구분한다. 공개되지 않은 급수를 선택 목록이나 잠긴 항목으로 보여주지 않는다.

검수 중인 50자를 전체 300자로 잘못 표현하지 않는다. 급수 전체 자료가 공식 수량·명단과 일치하기 전에는 해당 급수 대비가 완성되었다고 표시하지 않는다.

## 3. 화면과 전환 동작

### 헤더

기존 트랙과 같은 헤더 구조로 트랙·숙련도·학습 종류·찾기를 제공한다. 급수 선택 버튼과 범위 필터는 두지 않는다. 좁은 화면에서는 기존 헤더의 반응형 규칙을 따른다.

한자 소개·4지선다 퀴즈·쓰기 연습 모두 같은 피드의 카드로 제공한다. 쓰기 콘텐츠가 추가되어도 학습 종류 탭과 선택 밑줄을 표시하지 않는다. 헤더는 트랙·숙련도·찾기만 제공한다. 트랙 설명에 `한국어문회 기준`을 명시한다. 국가공인 표시는 해당 급수의 공식 상태를 별도로 검증한 경우에만 사용한다.

- 처음 한능검에 들어오면 공통 피드에서 공개 콘텐츠를 학습한다. 쓰기 연습은 검수된 자형이 있는 글자에 한해 카드 안의 선택적 `써보기` 동작으로 진입하고, 다음 카드로 학습을 이어간다.
- 재방문하면 기존 피드 복원 정책을 따른다. 학습 탭·목표 급수·범위 설정은 저장하지 않는다.
- 기존 외국어 트랙의 `단어 / 표현 / 상식` 선택은 별도로 보존한다.
- 복원할 카드의 콘텐츠가 비공개가 되면 학습 가능한 카드로 이동한다. 저장된 학습 기록은 삭제하지 않는다.
- 콘텐츠 로딩 실패와 공개 콘텐츠 없음은 각각 다른 상태와 안내를 제공한다. 네트워크 실패에는 재시도 버튼을 제공한다.

### 한자 카드

큰 한자 → 훈과 음 → 최초 읽기 배정 급수 → 검수된 활용 한자어 순서로 보여준다. 예를 들어 `山 / 메 산 / 8급`을 중심에 놓는다. 급수는 선택 버튼이 아닌 정적 정보다. 활용어의 학습 범위는 별도 검수하며 구성 한자의 급수만으로 단어의 시험 급수를 추정하지 않는다.

`한자`는 山·學처럼 글자를, `한자어`는 山川(산천)·學校(학교)처럼 한자에 바탕을 둔 단어를 학습한다. 한자어는 반드시 두 글자 이상인 것은 아니다. 한자 카드에서 글자와 훈음을 익히고, 카드 아래 활용 한자어의 뜻과 독음을 함께 확인한다. 독립 한자어 탭은 제공하지 않는다.

그림은 이해를 돕는 경우에만 선택적으로 사용한다. 추상적인 한자에 이미지를 억지로 배정하지 않는다. 그림이 없다는 이유로 한자를 피드에서 제외하지 않는다. 글꼴은 한국어 자형을 확인하고 `lang="ko"`로 렌더링한다.

### 카드·트랙 전환 시 진도

트랙 또는 공개 학습 대상이 바뀌면 피드의 예약 큐, 최근 노출 목록, 현재 문제, 임시 입력을 초기화한다. 저장된 학습 진도는 유지한다. 현재 학습 대상에 속하지 않는 항목이 이전 예약 큐에서 다시 나와서는 안 된다.

비동기 로더는 요청 당시 트랙·콘텐츠 버전과 현재 상태를 비교하거나 취소 신호를 사용한다. 늦게 도착한 응답이 현재 피드를 덮지 않게 한다. 답안 이벤트와 저장은 문제 생성 당시 트랙·항목에 연결한다.

### 화면 문구

- 급수는 `8급`처럼 짧게 표시한다. `8급 배정 한자` 같은 설명을 덧붙이지 않는다.
- 퀴즈의 `알맞은 훈음을 고르세요` 안내와 `정답은 메 산입니다` 같은 결과 문장은 화면에 표시하지 않는다. 선택지의 색·정오 기호로 결과를 보여주고, 스크린리더에는 숨겨진 상태 알림을 제공한다.
- 쓰기 칸의 입력 안내, 정답 비교 안내, 읽기 숙련도 제외 안내는 화면에서 생략한다. 숙련도 제외 정책은 그대로 유지한다.
- 한 획 취소·전체 지우기는 아이콘만 표시한다. 접근성 이름과 최소 44px 터치 영역은 유지한다.

### 읽기 판정

- 한자 선택은 같은 급수 범위에서 오답을 우선 선택한다. 검수된 유사 자형을 활용한다.
- 정답이 되는 글자가 둘 이상인 훈음은 문맥·추가 단서를 붙이거나 모든 허용 정답을 명시한다. 동음·동훈 문항에서 정답이 하나라고 임의로 가정하지 않는다.
- 훈음은 `훈`과 `음`의 허용 조합 목록을 사용한다. 각각의 허용값을 무조건 교차 조합해 정답을 늘리지 않는다.
- 훈음 퀴즈는 검수된 정답 한 개와 오답 세 개로 구성한다. 정답인 훈음 조합이 다른 보기에 중복되지 않게 검증한다. 선택지 ID로 판정하며 자유 입력·입력값 정규화·AI 의미 추정은 사용하지 않는다.
- 활용 한자어의 독음은 단어 문맥에 따른 두음법칙·속음을 반영해 검수한다. 글자별 대표음을 단순 연결하지 않는다. 활용어에는 답안 입력·정오 판정을 제공하지 않는다.
- 기존 `ChoiceCard`처럼 2×2 보기에서 한 번 선택하면 즉시 판정한다. 별도 확인 버튼은 없다. 정답 보기는 초록색, 선택한 오답은 붉은색으로 구분하고 기호도 제공한다. 결과 설명 문장은 시각적으로 표시하지 않는다. 답변 후 `aria-disabled`와 이벤트 가드로 중복 입력을 막고 키보드 포커스를 유지한다.
- 보기 아래 `모르겠어요`를 제공한다. 선택하면 정답을 공개하되 정답으로 기록하지 않는다. 답변 또는 포기 후에만 다음 카드로 이동할 수 있다.

### 읽기 숙련도

한자별 `한자 선택`과 `훈음 선택`을 별도 학습 항목으로 저장한다. 각 항목은 기존 FSRS 복습 간격을 활용한다. 두 문항은 모두 선택형이며 자유 회상 숙련도를 의미하지 않는다. 각 기술의 사다리는 고정 문항 단계로 두고, 현재 외국어의 문맥·철자 사다리를 적용하지 않는다.

한자가 읽기 숙련 상태가 되려면 두 항목이 모두 기존 숙련도 조건을 충족해야 한다. 기존 조건의 시간 기준은 `MASTERED_STABILITY = 21`을 재사용한다. 사다리 상한은 한능검용 값을 명시적으로 전달한다. 소개나 힌트 확인만으로 숙련도가 오르지 않는다.

헤더의 분모는 현재 공개된 학습 가능 한자 전체다. 공식 급수 수량이나 특정 목표 급수를 분모로 사용하지 않는다. 상세 보기에는 `학습 가능한 한자` 수량임을 명시한다.

예: 공개된 50자 중 20자가 두 읽기 항목 모두 숙련 상태이면 `20/50`이다. 이후 콘텐츠가 100자로 늘면 기록을 유지한 채 `20/100`이 된다. 활용 한자어 확인·쓰기 기록은 이 비율에 합산하지 않는다.

이는 읽기 학습 상태이며, 시험 합격률이나 전체 출제 영역의 완성도를 뜻하지 않는다. 활용 한자어에는 별도 숙련도나 학습 수량을 표시하지 않는다.

## 5. 쓰기 연습과 판정의 경계

### 사용자에게 제공하는 기능

- 손가락·펜·마우스로 쓸 수 있는 사각 입력 영역, 한 획 취소, 전체 지우기, 정답 보기.
- 각 획의 좌표와 순서를 수집한다. 화면을 캡처해 OCR에만 맡기지 않는다.
- Hanzi Writer [S4]를 어댑터로 연결하고, 검수된 획 데이터를 앱과 함께 제공한다. 외부 CDN을 실행 중 필수로 호출하지 않는다.
- 위치·모양·길이·방향·순서를 기준 획과 비교해 연습 피드백을 제공한다.
- 획 안내·자동 수정·정답 표시가 개입된 완료는 `도움받아 완료`로 기록한다. `onComplete`만으로 독립 쓰기 성공이나 FSRS 정답을 기록하지 않는다.
- 완료 표시는 `기준 획 연습 완료`로 한다. 한국어문회 답안이 정답으로 인정된다는 문구를 사용하지 않는다.

Hanzi Writer의 퀴즈는 획마다 정오를 알려 주고 정해진 획을 따라 진행한다. 안내선을 숨겨도 자유 답안 최종 채점과 동일하지 않다. 해당 라이브러리는 입력·획 검사의 후보이며, 한국어문회 손글씨 자동 채점기가 아니다.

### 획순 재생

- 각 한자에 공식 자료의 글자별 순서를 대조한 획 데이터가 있으면 소개 카드와 쓰기 칸에 재생 아이콘을 제공한다. 필순은 자체 추론·일반 규칙·중국어/일본어 데이터만으로 결정하지 않는다. 첫 획부터 마지막 획까지 공식 자료의 순서대로 그리며 완료한 획을 누적해서 남긴다.
- 재생·일시정지·이어 재생·처음부터 재생을 제공한다. 조작은 아이콘으로 표시하고 접근성 이름을 유지한다. 현재 획은 `1 / 3`처럼 짧게 표시한다. 자동 반복이나 카드 진입 시 자동 재생은 하지 않는다.
- 쓰기 칸에서는 기준 획을 구분되는 색으로 표시하고 사용자가 그린 획은 보존한다. 재생은 학습 정답·쓰기 성공으로 기록하지 않는다. 도움받은 쓰기를 별도 기록하는 기능은 후속 범위다.
- 카드 전환·닫기에서 재생을 취소하고, 백그라운드 전환에서는 일시정지한다. 빠른 재시작에도 이전 재생이 새 카드에 남지 않게 한다.
- 동작 줄이기 설정에서는 획을 움직여 그리는 대신 버튼을 누를 때마다 다음 획을 즉시 추가한다. 획 순서와 방향 정보는 검수된 데이터로 유지한다.
- 제품 구현은 로컬 SVG 중심선과 브라우저 Web Animations API를 사용한다. 데이터가 없는 글자는 재생 버튼을 숨기며 임의 필순을 자동 생성하지 않는다. 공식 쓰기 배정 여부와 획순 관찰 가능 여부는 별도다.
- 원문 도해를 대조한 14자의 경로만 `lib/hanja-strokes.ts`에 등록한다. SVG 좌표는 표현 수단이며 필순을 결정하는 근거가 아니다. Hanzi Writer 및 중국어/일본어 획 데이터를 한국어문회 필순의 근거로 쓰지 않는다.

### 공식 필순 원자료 확인 (2026-09-06)

- 한국어문회 공식 `시험 안내 → 학습자료 → 기타자료`에서 **「필순 정정 및 500자 필순」**을 확인했다. [공식 자료 검색 페이지](https://www.hanja.re.kr/kccpt/exam/otherData.do?search_option=subject&search_text=%ED%95%84%EC%88%9C).
- 공식 설명은 필순 예제, 한국어문교육연구회 지침서의 필순 정정·보충, 필순 원칙, 5급 500자의 필순을 수록하며 8급·7급·6급Ⅱ·6급·5급에서 이용할 수 있다고 명시한다. 이 안내를 상위 급수 전체의 필순 자료 확보로 확대 해석하지 않는다.
- 공식 다운로드를 통해 HWP 원본 `f37.hwp`의 응답과 문서 내 미리보기 텍스트를 확인했다. 파일 크기 750,080바이트, SHA-256 `4e191bbee54edd6db595f16fc83a15b9929eba0e3e01095da1e828c70e10760c`. 다운로드 식별자는 `file_seq=12751`, `target_id=115`이며 세션과 CSRF 처리가 필요한 POST 다운로드이므로 위 공식 페이지로 안내한다.
- 문서에 표시된 수정일은 **2010-03-22**다. 長의 첫 획을 세로획부터 쓰도록 조정한 정정과 필순 원칙 증보가 적혀 있다. 현재 공식 사이트에서 배포 중임을 확인했지만 그 이후 정정이 없다는 의미는 아니다. 구판 지침서보다 정정 내용이 우선함을 보존하고, 새 공식 정정이 확인되면 판본을 갱신한다.
- 공식 게시 설명·파일 다운로드·HWP 미리보기 텍스트와 14자의 전체 필순 도해를 확인했다. 500자의 개별 도해를 모두 판독한 상태가 아니다. 확인된 14자는 공식 순서를 따르는 자체 SVG 중심선을 사용한다.
- 각 글자의 데이터에는 공식 문서 ID·판본·원문 페이지/도해 위치·전사한 획 순서·대조 상태를 기록한다. 공식 근거가 없거나 도해를 판독하지 못한 글자는 임의 보완하지 않고 재생 대상에서 제외한다. 4급 이상은 한국어문회 공식 지침서·추가 정정 자료에서 글자별 근거를 확보한다. [공식 학습교재 안내](https://www.hanja.re.kr/kccpt/exam/studyInfo.do).
- 공개 다운로드와 앱 재배포·변환 허용 여부는 구분한다. 자료 이용 조건은 배포 전에 확인한다.

### 급수별 쓰기

6급Ⅱ부터 공식 쓰기 배정이 있다. 목표 급수를 선택하지 않으므로, 공개된 한자 중 쓰기 배정 근거와 자형 검수가 완료된 항목을 연습 대상으로 한다. 카드에는 읽기·쓰기의 최초 배정 급수를 구분한다. 예: `山 · 읽기 8급 · 쓰기 6급Ⅱ`.

현재 자유 쓰기 연습은 소개 카드의 `써보기`로 진입하고 헤더 탭은 없다. 모든 공개 한자에서 입력·취소·지우기·정답 겹쳐 보기를 제공하며, 읽기 숙련도와 공식 쓰기 배정의 완료 여부에 반영하지 않는다. 위의 공식 쓰기 배정 표시는 검수된 획 연습을 도입할 때 적용할 후속 설계다.

### 검수할 내용

- 공식 정자·약자 허용 조건과 국내 통용 자형. 중국 간체·일본 고유 약자를 자동으로 허용하지 않는다 [S3].
- 기준 획 데이터의 한국 자형·필순 적합성. Make Me a Hanzi는 중국어용, KanjiVG는 일본어용 자료이므로 검수 없이 시험 기준으로 사용하지 않는다 [S5][S6].
- 필순 오류와 완성 자형 오류를 구분한다. 일반 쓰기 정답 여부를 필순 하나만으로 결정하지 않는다 [S2].
- 동일 자형의 허용되는 작성 변형, 손가락 입력의 흔들림, 작은 화면에서의 입력 오차.

### 자유 쓰기 자동 판정의 출시 조건

현재 확보된 것은 정답 인정 원칙과 획 비교 구현이다. 한국어문회와 동등한 자동 판정 정확도, 글자별 허용 오차, 손글씨 평가 데이터셋은 아직 확보하지 않았다.

별도 후속 기능으로 구현할 경우 다음이 선행되어야 한다.

1. 전문가가 글자별 허용 자형과 판정 기준을 검수한다.
2. 여러 필자의 손글씨, 유사 글자, 획 누락·추가·방향 오류, 흐트러진 정답을 포함한 평가 데이터를 만든다.
3. 허용 오차를 조정하는 데이터와 평가 데이터를 필자 기준으로 분리한다. 정답과 오답의 비율도 함께 보고한다.
4. `오답을 정답 처리한 비율`, `정답을 오답 처리한 비율`, `판정 보류율`을 글자·기기별로 측정한다. 출시 허용치는 결과 검토 후 별도 결정한다.
5. 결과는 `정답 / 오답 / 판정 보류`로 구분한다. 보류를 자동 오답으로 계산하지 않는다.

이 조건을 충족하기 전에는 쓰기 숙련도 퍼센트를 제공하지 않는다. 글자 인식 후보가 정답과 같다는 사실만으로 획의 정확성까지 검증되었다고 처리하지 않는다.

### 터치와 접근성

입력 영역만 `touch-action: none`을 적용하고 영역 밖에서는 피드 스크롤을 유지한다. 포인터 캡처·취소·멀티터치·화면 크기 변경 시 임시 획 상태를 정리한다. 한 번의 제출을 중복 기록하지 않는다.

좌표는 화면 픽셀이 아닌 기준 좌표계로 변환하고, 고해상도 화면 비율을 반영한다. 지우기·취소·정답 보기에는 접근 가능한 이름과 키보드 조작을 제공한다. 그리기가 어려운 사용자는 읽기 학습으로 돌아갈 수 있고, 쓰기 미참여가 읽기 숙련도를 떨어뜨리지 않는다.

## 6. 데이터 설계

기존 `Concept.words`에 가짜 외국어 단어를 넣지 않는다. 한자 원본에 검수된 활용 한자어를 연결한다. 아래 경로와 필드는 구현 제안이며 아직 생성하지 않는다.

### 저장 경로

| 제안 경로 | 역할 |
| --- | --- |
| `content/hanja/manifest.json` | 스키마·콘텐츠 판본, 출처, 급수별 수량·공개 상태 |
| `content/hanja/characters/{gradeId}.json` | 해당 단계에서 처음 배정된 한자의 원본 데이터 |
| `content/hanja/assignments/{gradeId}.json` | 공식 읽기·쓰기 배정 ID 집합 |
| `content/hanja/strokes/{glyphId}.json` | 필요할 때만 불러오는 자형·획 데이터 |
| `content/hanja/sources.json` | 원자료 URL·확인일·판본·이용 조건·검수 근거 |

한자는 전체에서 한 번만 정의한다. 문자 ID는 정규 자형에 배정한 안정된 코드포인트 ID를 사용한다. 예: `u5c71`. 표기 수정이나 급수 변경으로 ID가 바뀌지 않게 한다. 호환 한자·이체자는 명시적인 매핑으로 관리하고 NFKC 변환만으로 서로 같은 정답이라고 판단하지 않는다.

### 주요 레코드

| 레코드 | 필수 필드와 의미 |
| --- | --- |
| Grade | `id`, `rank`, `label`, `expectedReadingCount`, `expectedWritingCount`, `releaseStatus` |
| Character | `id`, `glyph`, `introducedGradeId`, `hunEumAnswers`, `examples`, `radical`, `strokeCount`, `sourceIds`, `reviewStatus` |
| Assignment | `gradeId`, `readingCharacterIds`, `writingCharacterIds`, `sourceEdition` |
| Character.examples[] | `text`, `readingKo`, `meaningKo`, `sourceIds`, `reviewStatus`. 카드 하단 활용 예시이며 독립 학습 항목이 아님 |
| Glyph | `id`, `characterId`, `form`（正字/약자）, `acceptedPromptKinds`, `strokeAsset`, `reviewStatus`, `licenseId`, `sourceIds` |
| Release | `schemaVersion`, `contentVersion`, 급수별 `readingReady`, `writingReadyCount` |

`hunEumAnswers`는 훈·음의 허용 쌍이며 문맥 제한을 포함할 수 있다. `acceptedPromptKinds`는 문제에서 정자·약자·일반 한자 중 무엇을 요구하는지 구분한다. 한자어의 출제 범위는 구성 한자의 급수만으로 자동 확정하지 않는다.

공식 자료의 공개 여부와 재배포 허용은 별개다. 다운로드·변환 전에 이용 조건을 확인하고, 기출문제나 설명을 무단으로 복제하지 않는다. 획 데이터도 라이브러리 코드의 라이선스와 별개로 출처·조건을 보존한다. 조건 미확인 데이터는 배포 후보에서 제외한다.

### 빌드와 로딩

한능검 산출물은 `public/hanja/` 아래에 생성한다. 현행 `scripts/split.ts`는 `public/content` 전체를 지우고 다시 만들므로 해당 경로에 별도 쓰기 산출물을 두지 않는다.

매니페스트는 가볍게 유지한다. 공개된 문자 청크를 피드에 필요한 순서대로 로드하고, 활용 한자어는 해당 문자 청크에 포함하고 획 데이터는 연습 시작 시 지연 로드한다. 급수별 파일 분할은 내부 데이터 관리 방식이며 사용자 선택을 요구하지 않는다. 버전이 다른 매니페스트와 청크는 섞지 않고 재요청한다.

한능검을 열지 않은 외국어 학습자는 한자 데이터나 쓰기 라이브러리를 내려받지 않는다. 음성 생성·누락 검사 대상에도 한능검을 추가하지 않는다.

## 7. 설정과 진도 저장

| 키 | 용도 |
| --- | --- |
| `lingo.track` | 기존 방식으로 `hanja` 선택 저장 |
| `lingo.progress.hanja` | 한자 읽기 FSRS 상태. 기존 Progress 형식 사용 |
| `lingo.hanja.writing.v1` | 자형별 연습 완료·힌트 사용·기준 데이터 버전 |

학습 항목 키 예시:

- `hanja:char:u5c71:recognition`
- `hanja:char:u5c71:hun-eum`

급수·필터·콘텐츠 파일명은 키에 포함하지 않는다. 읽기 진도는 모든 급수에서 공유하지만 기존 JLPT·HSK·TOCFL과는 분리한다. 한자의 모양이 같다는 이유로 다른 시험의 읽기 진도를 가져오지 않는다.

쓰기 기록은 FSRS 정답과 분리한다. 원시 손글씨 좌표는 기본적으로 현재 연습 중에만 유지하고 분석·서버 전송·영구 저장을 하지 않는다. 판정 기준이 바뀌어도 과거 연습 완료가 새 기준의 성공으로 소급 해석되지 않도록 자형·판정 버전을 기록한다.

알 수 없는 설정은 기본값으로 처리한다. 콘텐츠에서 잠시 제외된 항목의 진도는 보존하되 현재 범위 집계에서 제외한다. 기존 트랙의 저장소 키와 PROGRESS_VERSION을 한능검 추가만으로 변경하지 않는다. 이후 스키마 변경이 필요하면 명시적인 마이그레이션을 별도로 설계한다.

### 권장 모듈 경계

- `lib/hanja/`: 타입, 급수 메타데이터, 콘텐츠 로더, 문항 생성, 답안 판정, 숙련도 집계.
- `components/hanja/`: 한자 카드와 그 안의 활용 한자어 영역, 쓰기 입력.
- `lib/learn-item.ts` 제안: 공통 학습 항목 타입을 현재 `lib/trivia.ts`에서 분리해 특정 덱이 공통 모델을 소유하지 않게 한다.
- `Track`은 외국어 분기만 `language: Language`를 갖고, 한자 분기는 별도 콘텐츠 종류와 지원 기능을 갖도록 한다. `zh`나 더미 언어를 한능검에 지정하지 않는다.
- 한능검 지원 기능은 음성 없음·그림 선택·지원 문항·쓰기 연습 가능 여부을 선언한다. 공개 콘텐츠의 준비 상태를 적용해 실제 노출 기능을 결정한다. 급수 선택은 현재 지원 기능에 포함하지 않는다.

한능검을 상식 카드로 위장하지 않는다. 기존 `entries as Entry[]` 같은 가정은 새 분기 이전에 안전하게 좁히도록 바꾼다. FSRS·예약 알고리즘을 복제하지 않고 공통 엔진에 연결하되, 한능검만을 위해 모든 기존 콘텐츠 형식을 한 번에 다시 작성하지 않는다.

피드의 공통 데이터에는 외국어 lang을 강제하지 않는다. 언어가 필요한 렌더러만 외국어 항목에서 언어를 얻고, 한자 렌더러는 한국어 자형과 자체 텍스트를 사용한다. 기존 키보드 정답·카드 재생 처리 역시 문항 종류로 좁힌다.

### 검색

한능검에서는 글자·훈·음·한자어로 검색할 수 있어야 한다. 기존 외국어 결과에 가짜 중국어 단어를 추가하지 않는다. 결과 유형에 한능검을 명시하고, 상세 카드에는 급수와 훈음을 보여준다.

전역 검색의 기존 외국어 결과는 유지한다. 한능검 결과를 선택하면 해당 한자 카드로 연결하며, 활용 한자어로 검색한 결과도 관련 한자 카드에 연결한다. 이때 목표 급수를 변경하는 동작은 없다. 검색 결과를 열거나 정답을 보는 것만으로 숙련도가 오르지 않는다. 획 데이터는 검색 색인에 포함하지 않는다.

## 9. 적용 범위와 후속 작업

### 전 급수 한자 학습

예시 10자의 기존 학습 방식을 전 15급수 5,978자로 확장했다. 급수별 파일에는 신규 배정자만 저장하고 낮은 급수부터 한 번씩 소개한다. 공식 대표훈음과 복수 훈음, 부수, 총획수, 원문 위치를 보존한다. 선택지는 같은 급수를 우선하며 정답으로 인정되는 훈음이 겹치는 글자는 오답에서 제외한다.

검색은 글자·호환 자형·복수 훈음·기존 한자어 예시를 지원한다. 결과는 60개씩 추가로 표시한다. 한자별 급수 표시, 기존 진도 보존, 4지선다, 자유 쓰기는 전 급수에 공통으로 적용한다. 특급Ⅱ의 공식 표기 4,918에는 다음자 중복 268개가 포함되므로 고유 자형은 4,650개다. 중복 카드를 만들지 않는다.

### 후속 문항과 획 데이터

부수·필순 문제·성어·반의어·유의어·동음이의어·약자·장단음·특급 한문은 각각 데이터와 문항 설계가 준비된 후 추가한다 [S2]. 읽기 배정 완료만으로 해당 급수의 모든 시험 영역 대비가 완료되었다고 표시하지 않는다. 필순 재생은 검증된 14자에서 시작해 공식 도해와 글자별 대조가 끝난 경우에만 확대한다. 자유 쓰기 자동 채점은 5절의 평가 조건을 통과해야 한다.

독립 한자어 학습, 급수 선택·누적/신규 범위 필터·급수별 숙련도는 후속 검토 대상이다. 필요해질 때 다른 트랙의 수준 선택과 함께 통일된 UX를 설계한다.

## 10. 수용 기준과 검증

### 데이터

- 급수 15개, ID·rank 중복 없음, 읽기·쓰기 공식 수량 일치.
- 공개된 모든 한자의 ID와 배정 근거가 존재하고 중복되지 않음. 급수 전체 준비를 표시하려면 공식 읽기 집합과 일치하고 하위 집합을 모두 포함해야 함.
- 쓰기 ID가 같은 급수의 읽기 집합에 포함되고 공식 쓰기 명단과 일치함. 수량만 맞춘 임의 명단은 실패.
- 신규 범위 = 현재 읽기 집합 − 직전 읽기 집합. 7급의 신규 50자를 확인함.
- 정답 변형과 오답 보기가 충돌하지 않음. 한자어 독음·급수·출처를 검증함.
- 출처·이용 조건·검수 상태가 없는 데이터는 공개 산출물에 포함되지 않음.

### 학습·저장

- 콘텐츠 확장·배정 정보 변경 후에도 동일 한자의 두 기술 기록이 같은 키로 유지됨. 숙련도 분모는 공개된 학습 가능 한자 수와 일치함.
- 재인만 숙련된 한자는 읽기 숙련 수에 포함되지 않음. 활용 한자어 확인·쓰기·힌트 사용도 읽기 분자를 올리지 않음.
- 트랙·공개 대상 변경 후 이전 예약 항목이 출제되지 않음. 같은 트랙의 카드 전환은 예약 큐를 유지함. 빠르게 전환해도 응답과 진도가 섞이지 않음.
- 한능검 진도가 기존 트랙 진도에 영향을 주지 않음. 기존 저장 데이터 fixture로 회귀 검증함.
- 쓰기 화면을 포함해 모든 한능검 화면에 학습 탭이 없음. 검수된 쓰기 콘텐츠가 없으면 카드의 써보기 동작도 나타나지 않음. 읽기 8급인 글자도 검수된 쓰기 배정이 있으면 연습 가능하며 두 급수를 구분해 표시함.

### UI·성능

- 이미지가 없어도 모든 공개 한자가 출제됨. 한능검에서 오디오 객체 생성·음성 요청·재생 버튼이 없음.
- 외국어 진입 시 한자 데이터·Hanzi Writer 청크가 로드되지 않음. 한자 읽기만 할 때 획 데이터가 로드되지 않음.
- 훈음 퀴즈는 정확히 네 보기·모르겠어요를 제공하며 정답·오답·포기·중복 클릭·다음 카드 동작을 확인함. 한자어 탭·별도 독음 퀴즈가 없고 한자 카드 하단의 활용 예시는 유지됨. 급수 선택·범위 필터가 초기 UI에 없고 한자 카드·검색 결과에 최초 읽기 급수가 표시됨. 좁은 화면, 키보드로 네 보기 선택, 스크린리더 이름, 로딩·실패·준비 상태를 확인함.
- 쓰기 영역 밖 스크롤, 포인터 취소, 한 획 취소, 전체 삭제, 중복 제출 방지가 동작함.
- 힌트·강제 완료·자동 보정 후 완료가 독립 정답으로 저장되지 않음.

실제 구현 시 순수 범위·채점·진도 테스트, 기존 테스트, 타입 검사, 빌드와 브라우저 검증을 수행한다. 설계 문서만 추가하는 이번 작업에서는 문서 구조·급수표·참조 경로·변경 범위만 검증한다. 다른 세션의 산출물을 재생성하는 빌드나 콘텐츠 스크립트는 실행하지 않는다.

## 11. 다른 세션과의 작업 경계

이번 작업의 작성 대상은 `docs/hanja-track-design.md`와 `.visualstorming/`의 독립 화면 시안이다. `spec.md`는 현재 구현의 기준 문서이므로 설계안 때문에 먼저 변경하지 않는다. 앱 소스·콘텐츠·잠금 파일·생성 파일·git 인덱스는 수정하지 않는다.

설계 시작 시 다른 작업의 변경을 확인한 파일: `content/body.json`, `content/city.json`, `content/clothes.json`, `content/family.json`, `content/food.json`, `content/home.json`, `content/idea.json`, `content/nature.json`, `content/school.json`, `content/transport.json`, `content/travel.json`, `lib/audio-have.ts`, `lib/levels-stamp.ts`.

이 목록은 소유권 목록이나 고정 상태가 아니다. 실행 중 새 변경이 생길 수 있다. 구현을 시작할 때 현재 변경과 인터페이스를 다시 확인하고, 공유 파일은 다른 세션의 변경을 보존하는 부분 편집으로 연결한다. 모든 변경을 일괄 스테이징하거나 되돌리지 않는다.

## 12. 근거와 미확정 사항

공식 급수·문항·답안 인정 기준은 2026-09-06 조사 결과다. 아래 자료는 역할이 다르다. 시험 기관 자료는 출제·정답 기준, 라이브러리는 구현 근거, 공개 획 데이터는 검수할 원자료 후보다.
