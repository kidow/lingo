# 訣·紋 쟁점 3획 방향 확인 및 21획 적용

2026-09-13. 이전 자형·경로 보정 검토에서 보류했던 **訣 11획, 紋 4·5획**을 국내 사전 제공자의 실제 애니메이션으로 확인했다. 기존 18획 검토와 합쳐 **訣 11획·紋 10획을 런타임에 적용**했다.

전체 5,978자 중 **1,478자 재생 가능, 4,500자 미적용**이다. 3급II 신규 배정 500자는 **488자(97.6%) 적용**, 12자 미적용이다. 여기서 급수 집계는 그 급수에서 처음 배정된 글자만 센다.

## 새 방향 근거

- 제공자: [e-hanja](http://www.e-hanja.kr/), 오픈마인드지앤에이. [개발자 공식 앱 설명](https://play.google.com/store/apps/details?hl=ko&id=kr.openmindgna.ehanja)에서 사전 운영 주체와 필순 애니메이션 제공을 확인했다.
- [訣 원본 애니메이션](http://img.e-hanja.kr/hanjaSvg/aniSVG/8A00/8A23.svg): 정확히 訣·11획인 검색 결과에서 열었다. 11획이 중앙 접점에서 오른쪽 아래로 길게 이어지는 동작을 4개 중간 화면으로 관찰했다.
- [紋 원본 애니메이션](http://img.e-hanja.kr/hanjaSvg/aniSVG/7D00/7D0B.svg): 정확히 紋·10획인 결과에서 열었다. 4획은 중앙 줄기가 위에서 아래로, 5획은 별도의 왼쪽 하단 획이 왼쪽 아래로 진행한다. 각 3개 중간 화면을 관찰했다.

기존 사전 화면의 재생 동작을 사용했다. 각 획의 클립 번호·재생 지연·지속 시간과 화면 캡처 직전에 읽은 dash offset을 [direction-review.json](direction-review.json)에 기록했다. offset은 화면 자체의 정확한 촬영 시각을 뜻하지 않는다. 관찰한 화면 10개는 저장·재배포하지 않았다.

**사전 제공자 근거이며 한국어문회·교육부의 인증이 아니다.** 기존 국내 번호 도판, 대만 교육부 개별 획 대조 및 경로 검토에 이번 3획 관찰을 보완했다. e-hanja의 訣 1획은 가로획, 紋 7획은 세로획으로 후보의 비스듬한 점과 다르므로, 해당 두 획의 승인이나 21획 전체 자형 일치 근거로 사용하지 않았다. 다른 글자도 이 자료만으로 일괄 승인하지 않는다.

## 경로와 근거의 분리

실제 재생 경로는 [이전 후보](../hanja-g3ii-gyeol-mun-2026-09-13/candidate-paths.json)를 그대로 사용했다. 訣은 고정 Make Me a Hanzi 원본 11획, 紋은 같은 원본 8획과 이미 검토된 紅의 4·5획을 변환한 2획이다. 이번 작업에서 새로 그린 획은 없다. 紋 4·5획의 원본 인덱스는 `null`로 유지해 보정 사실을 보존한다.

사전 SVG의 외곽선·중심선·CSS·스크립트는 복사하지 않았다. 원본 URL·바이트 수·해시와 관찰 기록만 남겼다. 실제 배포 경로의 저작권·변경 내역은 [공개 고지](../../public/hanja-strokes/dictionary-reviewed.README.md)에 적었다.

## 구현과 검증

- `lib/hanja-stroke-dictionary.ts`: `ehanja-crosschecked`라는 별도 출처로 두 글자만 허용한다. 출처 위치·전체 범위·획수·경로 해시·원본 인덱스가 다르면 거부한다.
- `scripts/hanja-stroke-dictionary.ts`: 증거 파일 8개, 고정 원본, 紅 기증 획을 검증하고 21획을 재현한다. prebuild 검증에 연결했다.
- `scripts/hanja-stroke-audit.ts`: 시험 주관 기관 자료와 구별해 집계하며 실제 고정 원본으로 경로를 재구성한다.
- `node --test 'lib/hanja*.test.ts'`: **167개 통과**, 실패 0. 증거·경로 변조, 출처 오표기, 인덱스 누락 등을 거부하는 검사 7개를 추가했다.
- 기존 후보 검증기: 21획·100개 획 쌍 확인. 경로는 이전 검토와 동일하며, 후속 적용된 2자를 인식하도록 갱신했다.
- `pnpm exec tsc --noEmit` 및 `pnpm exec next build` 통과. 후자는 타입 검사와 7개 정적 페이지 생성을 포함했다. 공유 콘텐츠 생성기를 재실행하지 않기 위해 `pnpm run build`의 prebuild 전체 실행은 생략했고, 새 데이터 검증은 별도로 실행했다.

기존 재생 UI는 바꾸지 않았다. 이번 회차에 직접 눈으로 확인한 움직임은 외부 사전 원본이며, 앱에서 두 글자의 재생 화면을 추가 확인하지는 않았다. 검증 결과는 [verification.json](verification.json)에 기록했다.
