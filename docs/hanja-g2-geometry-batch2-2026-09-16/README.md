## 대조와 보정

세 글자의 전체 실행 단계를 각각 확인했다. 부수 이름이나 총획수만으로 경로를 나누거나 승인하지 않았다.

- 董·藤은 초두가 후보 3획·사전 4획이었다. 왼쪽 가로→왼쪽 세로→오른쪽 가로→오른쪽 세로 순으로 분리하고 중앙 간격을 유지했다.
- 董은 **11획 아래 가로→12획 관통 세로** 순서가 원 후보와 달랐다. 순서를 바로잡고, 5획과 초두의 간격, 8·9·10획의 연결, 12획의 직진 방향과 위아래 접점을 보정했다.
- 藤은 **9획 왼쪽 삐침·10획 오른쪽 점**의 방향이 원 후보와 달랐다. 위치별 방향을 보정했다. 月 안쪽 가로 두 개를 연결하고, 14획이 첫 가로 부근에서 시작하여 다음 가로를 가로지르도록 고쳤다. 초두·月·아래 점과 갈고리는 재생 선폭 5에서도 서로 구분되도록 조정했다.
- 鄧은 오른쪽 부수의 윗꺾음과 아래굽음이 원 후보에서 한 획이었다. 사전의 13·14획 경계에서 나누고 마지막 세로를 15획으로 유지했다. 상단 점·가로의 간격, 내려가는 획의 시작점, 口의 연결, 아래 삐침의 시작·끝도 보정했다.
- 보정·작성된 최종 경로는 **28개**(董 7·藤 13·鄧 8), 유지한 최종 경로는 **19개**다. 전 47획의 순서·주요 진행 방향·누적 상태를 대조하고, 변경된 획과 최종 자형을 다시 확인했다.
- 결과는 단순화된 손글씨 중심선이다. 후보의 기울기·붓 진입 모양을 일부 유지하며 정적 명조 SVG의 외곽선을 그대로 재현하지 않는다.

## 출처와 보관 범위

[e-hanja 董](http://img.e-hanja.kr/hanjaSvg/aniSVG/8400/8463.svg), [藤](http://img.e-hanja.kr/hanjaSvg/aniSVG/8500/85E4.svg), [鄧](http://img.e-hanja.kr/hanjaSvg/aniSVG/9100/9127.svg)의 실제 상세 페이지 iframe 주소를 재확인했다. 사전 표시 획수·실행 단계·카탈로그는 각각 13·19·15획으로 일치한다. XML 배치 순서가 아니라 실행 지연 시간 순으로 대조했다.

고정 버전 Ko·Ja·MM 자료를 NFKC 호환문자까지 검색했지만 목표 획수와 일치하는 대체 후보는 없었다. 경로는 기존 Arphic Public License 출처와 고정 해시를 유지한다. 사전은 국내 민간 자료이며 시험 주관 기관의 공식 인증으로 표시하지 않는다. 런타임 출처는 `ehanja-crosschecked`다.

사전 SVG·HTML·이미지·화면 캡처는 저장하지 않았다. 원본은 RAM에서만 처리하고 URL·해시·실행 메타데이터·직접 작성한 관찰과 허용된 후보·보정 경로만 남겼다.

## 검증과 파일

한자 테스트 **54개 파일**과 TypeScript 검사를 통과했다. 새 회귀 테스트 8개는 44개 원본 획에서 47개 승인 획의 재현, 초두 간격·순서, 내부 가로 연결, 董 11·12획 순서, 藤 9·10획 방향과 14획 시작점, 鄧의 세 획 부수, 펜을 떼는 지점의 간격, 출처·경로·검토 기록 변조 거부를 확인한다. 기존 전체 등록부 검사에도 이번 묶음을 추가했다.

- `originals.json`·`acquire.mjs`: 고정 버전 후보와 읽기 전용 출처 재확인.
- `source-checks.json`·`initial-observations.json`·`observations.json`: 전 획 근거와 전후 관찰.
- `proposals.json`·`corrections.json`·`candidate-paths.json`·`review.json`: 명시적 획 대응과 보정 이력.
- `prepare.mjs`·`verify.mjs`·`checks.json`: 승인 경로 재생성·공개 데이터 일치·진행 현황 검증.
- `progress.json`·`next-batch.json`: 현재 런타임 집계와 다음 검토 목록.
- `serve.py`: 출처를 디스크에 저장하지 않는 임시 로컬 검토 화면.

`node docs/hanja-g2-geometry-batch2-2026-09-16/verify.mjs`로 자료·경로·등록·집계를 재검증한다.
