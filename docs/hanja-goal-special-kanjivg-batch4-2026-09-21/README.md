# 麕 19획 — 원본 굵기로 보류 해제

특급 麕의 전체 19획을 국내 e-hanja 필순과 대조하고 실제 런타임에 적용했다. 한국어문회 공식 인증으로 표시하지 않는다.

## 근거와 판단

- [고정 KanjiVG 원본](https://raw.githubusercontent.com/KanjiVG/kanjivg/422b5538595676da918c288a4230cb5e22a1ee7e/kanji/09e95.svg): CC-BY-SA-3.0, © Ulrich Apel and contributors. 전체 파일 SHA-256은 candidates.json에 고정했다.
- [국내 사전 대조](http://img.e-hanja.kr/hanjaSvg/aniSVG/9E00/9E95.svg): 19획. 비공개 그래픽은 RAM에서만 보며 저장하지 않았다.
- 원본은 109 좌표계에서 굵기 3을 지정한다. 100 좌표계에서는 **300/109 = 2.7522935779816513**이다. 이 메타데이터의 확인 기록은 [앞 배치](../hanja-goal-special-kanjivg-batch3-2026-09-21/source-style-followup.json)에 있다.
- 이전 비교 굵기 4 / 앱 굵기 5에서 내부 禾 세로획 16이 테두리 19와 맞닿았다. 원본 굵기로 **19개 누적 상태와 완성형**을 다시 눈으로 대조하여 분리된 간격과 식별성을 확인했다. 원본 경로와 1–19 순서는 그대로다. 점 추가·역전·분할·병합은 없다.
- 이 판정은 앞 배치 麕 보류를 대체한다. 앞 배치의 해시 고정된 findings.json은 변경하지 않았다. 曁은 여전히 보류다. Kaisho의 방향/갈고리 문제도 해제하지 않았다.

## 구현

dictionary 데이터에 선택적 strokeWidth를 추가했다. 이 배치 로더만 검토한 굵기를 정확히 허용한다. 플레이어는 해당 값을 사용하고, 값이 없는 기존 데이터는 굵기 5를 유지한다. 재생 타이밍·상태·모션 접근성·쓰기 입력 코드는 바꾸지 않았다.

candidates.json은 공개 경로, normalized.json은 균등 축척 결과, findings.json은 검토 근거다. build.mjs가 런타임 번들을 재현한다. serve.py는 사전 그래픽을 RAM에서만 대조하며 원본/정규화 좌표계에 맞는 굵기를 적용한다.

## 검증

- 한자 테스트 **794개 통과**, 타입 검사 통과.
- 분리 체크아웃의 프로덕션 빌드 통과. 임시 HanjaCard 검증 페이지를 사용했으며 실제 수정된 제품 파일들은 작업 트리와 바이트 단위로 같음을 확인했다.
- Desktop Chrome에서 麕 학습 자동재생 0→19, 다시 재생 1→19, 쓰기 진입 자동재생 1→19, 쓰기 다시 재생 1→19 및 재생 종료 버튼 상태 확인.
- 완성 화면에서 내부 세로획/아래 테두리 분리 확인. 쓰기 오버레이는 SVG 하나이며 stroke-width는 300/109.
- 캔버스 드래그로 1획 입력, 전후 canvas·dialog 좌표 동일, touch-action:none 유지.
- 餒는 기본 굵기 5와 자동재생 1→16 유지. 앱 콘솔 오류 0. 실제 모바일 기기 검증은 수행하지 않았다.
- React 검토: 기존 훅·효과·상태를 그대로 두고 렌더 시 원시값 하나만 선택한다.
