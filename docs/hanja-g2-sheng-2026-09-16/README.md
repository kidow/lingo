# 晟 11획 경계·전체 경로 검토

2026-09-16. **晟 1자·11획을 적용했다.** MM 후보의 5·6획 순서를 교환하고, 내부 가로와 갈고리를 두 획으로 나눴으며, 日 내부 가로획 접점을 보정했다.

## 근거와 해석 범위

- [한국어문회 상담 10026](https://www.hanja.re.kr/klea/counsel/hanjaDetail.do?id=10026)은 晟의 본자 획수를 日 4 + 戊 5 + 丁 2 = 11로 설명한다. 丁 부분을 한 획으로 잇는 成의 속자와 구별한다. 신선한 응답의 상태·크기·해시와 직접 작성한 해석을 `count-basis.json`에 기록했다.
- [한국어문회 필순 자료](https://www.hanja.re.kr/kccpt/exam/otherData.do)의 `f37.hwp` → `BIN002A.gif` 19행 **成 7획**을 다시 확인했다. 내부 가로가 3획, 내려가는 갈고리가 4획인 경계와 순서를 확인했다. 문서 SHA-256은 `4e191bbee54edd6db595f16fc83a15b9929eba0e3e01095da1e828c70e10760c`이다.
- [e-hanja 晟 애니메이션](http://img.e-hanja.kr/hanjaSvg/aniSVG/6600/665F.svg)은 **10단계**다. 열 단계의 전체 순서·방향·자형을 직접 비교하되, 합쳐진 7단계는 위 두 공식 자료로 경계를 보강했다.
- 좌표는 [고정된 Make Me a Hanzi 판본](https://github.com/skishore/makemeahanzi/tree/bddc96d41bef78427ed0e034e9f7e31d71fd1b92)의 허가된 medians에서 만들었다. 사전 경로를 복사하지 않았다. Arphic 라이선스는 기존 배포 경로에 유지한다.

**晟 전체의 11단계를 직접 보여 주는 원문은 확보하지 않았다.** 이번 결과는 晟을 특정한 공식 획수 설명, 공식 成 경계 도해, 晟 전체 사전 재생을 결합한 교차검토다. 공식 기관이 이 SVG 좌표를 인증했다는 뜻이 아니다. 런타임은 기존 `ehanja-crosschecked` 분류를 유지하며, 사전 방향 근거도 실제 1~10단계로 기록한다. 이 판정을 다른 부수나 미검토 글자에 자동 확대하지 않는다.

## 전 획 대조

| 적용 획 | MM 원본 | 사전 재생 단계 | 판정 |
|---|---:|---:|---|
| 1 | 1 | 1 | 아래로 |
| 2 | 2 | 2 | 오른쪽 후 아래로 |
| 3 | 3 보정 | 3 | 日 안쪽 가로의 양쪽 접점 보강 |
| 4 | 4 | 4 | 日 닫는 가로 |
| 5 | 6 | 5 | 아래로 내려가 왼쪽으로 삐침 |
| 6 | 5 | 6 | 왼쪽→오른쪽 가로 |
| 7 | 7 앞부분 | 7 앞부분 | 공식 成 3획과 晟 丁 2획 설명에 따른 가로 |
| 8 | 7 뒷부분 | 7 뒷부분 | 공식 成 4획에 따른 아래쪽 갈고리 |
| 9 | 8 | 8 | 오른쪽 아래로 굽어 올라오는 갈고리 |
| 10 | 9 | 9 | 오른쪽 위→왼쪽 아래 삐침 |
| 11 | 10 | 10 | 오른쪽 아래 점 |

원본 사전 SVG의 XML 순서는 재생 순서와 다르다. CSS 시작 시간으로 정렬한 XML 인덱스는 **7,8,9,10,1,2,3,4,5,6**이다. 화면 확인 결과 사전 5획은 삐침, 6획은 가로이며, MM 후보가 이 두 획을 반대로 가진다. 메타데이터만 보고 두 자료가 같은 순서라고 처리하지 않았다.

원본 7획을 나눈 두 경로는 같은 지점에서 이어지고, 다시 연결하면 원본 경로와 같다. 새로운 획 모양을 끼워 넣어 숫자만 맞추지 않았다. 보정한 日 가로는 오른쪽 변에 닿도록 연장했다. 11개 결과 경로와 누적 자형을 브라우저에서 다시 살폈다.

`count-basis.json`의 `dictionaryToRuntime`과 `licensedToRuntime` 배열은 **런타임 획 순서로 나열한 원본 단계 번호**이며, `componentToRuntime`은 공식 成의 1~7획에 대응하는 런타임 번호다.

## 적용·검증

- 배포 데이터: `public/hanja-strokes/dictionary-reviewed-g2-sheng.json`
- 런타임 모듈: `lib/hanja-stroke-dictionary-g2-sheng.ts`
- 오프라인 재구성·증거 고정: `scripts/hanja-stroke-dictionary-g2-sheng.ts`
- 출처와 경계, 5·6획 교환, 잘못된 10획 조회 차단, 증거 변조, 라이선스 출처 바꿔치기를 검사한다.
- 한자 테스트 **50개 파일·295개**, HWP 파서 **7개**, 메모리 검토 도구 **25개** 통과.
- `pnpm run build`의 TypeScript 및 정적 생성 통과. 첫 빌드에서 테스트 fixture의 readonly 배열 변경을 발견해 수정하고 다시 통과했다.
- 원본 HWP·사전 SVG·이미지·HTML·스크린샷은 파일로 저장하지 않았다. 검토 서버는 메모리에서만 원문을 처리한다.

재현:

```sh
node docs/hanja-g2-sheng-2026-09-16/verify.mjs
node --test lib/hanja-stroke-dictionary-g2-sheng.test.ts
python3 -B docs/hanja-g2-sheng-2026-09-16/serve.py
```

서버의 `/official`은 成 공식 누적 도해, `/proposal?start=5&end=8`은 분리된 두 획을 포함한 후보 비교다. 사전 7단계를 11단계로 위장하지 않고, 두 후보 획이 같은 원본 단계에 대응함을 표시한다.
