# 특급II 齎~澍 50자 검토 — 50자·648획 반영

2026-09-18 · **50자 전부 반영, 보류 없음**

[11차 垣~梓](../hanja-special2-batch11-2026-09-18/README.md)의 `next-batch.json`에 고정한 후보 50자를
같은 방식으로 대조했다. 첫 대조에서 36자가 일치했고, 14자는 보정 후 전체 획을 다시 확인했다.
허가된 중간선 634획을 유지하고 14획을 국소 보정했으며, 9자의 획 순서를 바꿨다.
MM 원본 35자, Ja 원본 15자에서 출발했다. 이번 회차에는 보류한 글자가 없다.

## 보정

| 보정 대상 | 변경 |
| --- | --- |
| 苧·薺 | 艹의 十 둘을 각각 가로 다음 세로 (1·2, 3·4획 교환) |
| 齎·霽·薺·臍 | 齊 아래 틀의 안쪽 가로 둘을 긴 오른쪽 세로보다 먼저 (12~14, 20~22, 16~18, 16~18획 재배열) |
| 勣·瀞 | 責·青 윗부분의 가로 둘을 세로획보다 먼저 (2·3, 5·6획 교환) |

| 翟·摺 | 羽 안쪽 네 획(2·3·5·6, 5·6·8·9획)을 왼쪽 아래 방향으로 반전·역방향 |

같은 회차의 諍·蚤(Ja)는 爫·叉의 점을 사전과 같은 방향으로 써서 그대로 뒀고,
筌·詮·鈿·玎처럼 王·田의 가로가 이미 세로보다 앞선 글자도 그대로 뒀다.

부수 유사성으로 승인하지 않았다. 각 글자의 사전 전체 필순을 순서대로 보고,
색으로 나눈 25% 진행 구간에서 방향·펜 떼기·획 경계·완성 자형을 대조했다.
보정 14자는 변경 획뿐 아니라 전체 획을 재대조했다.

[direction-probe.mjs](direction-probe.mjs)가 60°를 넘는 획 38개(14자)를 표시했고,
14자 모두 보정으로 이어졌다. 표시만 되고 그대로 둔 획은 없다.
齊·羽·責처럼 덩어리로 얽힌 자리는 획 끝점 좌표를 숫자로 확인한 뒤 판정했다.
사전이 세로로 긋고 허가 원본이 기울여 쓰는 짧은 점이 45~60° 구간에 16개 더 있었다.
1~11차와 같은 기준으로 임계 아래는 허가된 중간선을 그대로 뒀다.
苧·薺의 원문은 가로 이동 `translate(12, -y)`를 쓴다. 이동은 방향 벡터를 바꾸지 않는다.

## 근거와 재현

- [observations.json](observations.json): 50자 판정, 14자의 첫 판정·보정·재대조 기록, 8방향 코드

- [candidate-paths.json](candidate-paths.json), [review.json](review.json): 승인 경로와 증거 해시
- [prepare.mjs](prepare.mjs): 읽기 전용 승인 데이터 재현
- [verify.mjs](verify.mjs): 재현 결과·공개 데이터·적용 수·다음 후보 검증. 이전 회차 보류 글자는 큐에서 뺀다
- [checks.json](checks.json), [progress.json](progress.json): 이번 검증과 전체 진행 현황
- [next-batch.json](next-batch.json): 다음 侏~倜 50자·621획 후보
- [acquire.mjs](acquire.mjs), [source-checks.mjs](source-checks.mjs), [serve.py](serve.py): 원본 고정·원문 확인·검토 시트

필순 근거는 e-hanja 사전이며, **한국어문회 인증으로 표시하지 않는다.**
재생 중간선은 Arphic Public License의 고정 MM·Ja 원본에서 출발했다.
사전의 경로·마스크·영상·스크린샷을 파일에 저장하거나 배포하지 않았다.
자형의 구조와 진행 방향을 비교한 것으로 폰트 외곽선의 픽셀 일치나 필기 채점이 아니다.
