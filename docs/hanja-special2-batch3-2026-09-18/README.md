# 특급II 竅~犢 50자 검토 — 49자·610획 반영, 犢 보류

2026-09-18 · **49자 반영, 1자 보류**

[2차 涇~赳](../hanja-special2-batch2-2026-09-18/README.md)의 `next-batch.json`에 고정한 후보 50자를
같은 방식으로 대조했다. 첫 대조에서 41자가 일치했고, 8자는 보정 후 전체 획을 다시 확인했으며,
犢 한 자는 자형이 달라 보류했다. 허가된 중간선 604획을 유지하고 6획을 국소 보정했으며,
5자의 획 순서를 바꿨다. MM 원본 36자, Ja 원본 14자에서 출발했다.

## 보류 — 犢

사전은 賣의 가운데를 **四**로 쓴다. 안쪽이 儿이어서 10획은 왼쪽으로 길게 삐치고
11획은 내려가다 오른쪽으로 꺾인다. 허가된 MM 원본은 **罒**로, 안쪽이 짧은 세로 두 개다.
획 순서를 바꾸거나 한 획을 국소 보정해서 맞출 수 있는 차이가 아니라 **구성 요소의 자형 차이**다.
부수만 비슷하다고 승인하지 않는다는 원칙에 따라 런타임에 넣지 않았고,
`observations.json`의 `checks.glyphForm`을 `mismatch`로 남겼다.
牛 4획, 士 3획, 貝 7획은 일치한다. 사전과 같은 자형의 원본이 생기면 다시 본다.
보류한 글자는 다음 회차 후보에서도 빼 둔다. 그렇지 않으면 매 회차 같은 이유로 다시 보류된다.

耳·堇·隹처럼 두 획 교환으로 풀리지 않는 자리는 후보 중간선 좌표로 각 획의 위치를 재어
어느 획이 어디로 옮겨지는지 정했다. 이번 회차에 [endpoints 출력](#근거와-재현)을 쓴 것도 같은 이유다.

부수 유사성으로 승인하지 않았다. 각 글자의 사전 전체 필순을 순서대로 보고,
색으로 나눈 25% 진행 구간에서 방향·펜 떼기·획 경계·완성 자형을 대조했다.
보정 8자는 변경 획뿐 아니라 전체 획을 재대조했다.

[direction-probe.mjs](direction-probe.mjs)가 60°를 넘는 획 17개(9자)를 표시했고,
8자는 보정으로, 犢 한 자는 보류로 이어졌다. 覃의 원문은 가로 이동 `translate(12, -830)`을 쓴다.
이동은 방향 벡터를 바꾸지 않는다.

- [observations.json](observations.json): 50자 판정(49 승인·1 보류), 8자의 첫 판정·보정·재대조 기록, 8방향 코드

- [next-batch.json](next-batch.json): 다음 牘~褸 50자·784획 후보
- [acquire.mjs](acquire.mjs), [source-checks.mjs](source-checks.mjs), [serve.py](serve.py): 원본 고정·원문 확인·검토 시트

필순 근거는 e-hanja 사전이며, **한국어문회 인증으로 표시하지 않는다.**
재생 중간선은 Arphic Public License의 고정 MM·Ja 원본에서 출발했다.
사전의 경로·마스크·영상·스크린샷을 파일에 저장하거나 배포하지 않았다.
