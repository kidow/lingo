# 1급 疋~弧 50자 검토 — 50자·657획 반영

2026-09-20 · **50자 반영, 보류 없음**

[1급 19차 跆~披](../hanja-g1-batch19-2026-09-20/README.md)의 `next-batch.json`에 고정한 후보 50자를
같은 방식으로 대조했다. 첫 대조에서 23자가 일치했고, 27자는 보정 후 전체 획을 다시 확인했다.
허가된 중간선 654획을 유지하고 3획을 국소 보정했으며, 25자의 획 순서를 바꿨다.
이번 회차는 부수 단위로 순서가 어긋난 자리가 특히 많았다.
MM 원본 41자, Ja 원본 9자에서 출발했다.

같은 회차의 噓처럼 虍의 순서가 이미 맞는 글자와, 眩·醯처럼 玄·充의 점이 임계 아래로만 기우는 글자는 손대지 않았다.

부수 유사성으로 승인하지 않았다. 각 글자의 사전 전체 필순을 순서대로 보고,
색으로 나눈 25% 진행 구간에서 방향·펜 떼기·획 경계·완성 자형을 대조했다.
보정 27자는 변경 획뿐 아니라 전체 획을 재대조했다.

[direction-probe.mjs](direction-probe.mjs)가 60°를 넘는 획 42개(18자)를 표시했고,
모두 보정으로 이어졌다. 표시만 되고 그대로 둔 획은 없다.
여기에 더해 사전과 허가 원본의 획 끝점을 글자마다 맞대응시켜, 방향은 같지만 순서가 어긋난
謔·瘧·轄·緘·絢·骸·俠·挾·狹·頰·鹹의 자리를 찾아냈다. 프로브만으로는 걸리지 않는 자리다.
재배열·역방향·세로 보정을 넣은 뒤 50자 657획의 대응을 다시 계산해 60°를 넘는 획이 남지 않음을 확인했다.
45~60° 구간의 방향 차이는 보정 뒤 9개였다. 모두 사전이 세로로 긋고 허가 원본이 기울여 쓰는 짧은 점(瘧·咳·劾·嚮·眩·醯)과
轄·骸·駭의 짧은 획으로, 이전 회차와 같은 기준으로 임계 아래는 허가된 중간선을 그대로 뒀다.
荊의 원문은 가로 이동 `translate(12, -y)`를 쓴다. 이동은 방향 벡터를 바꾸지 않는다.

## 근거와 재현

- [observations.json](observations.json): 50자 판정, 27자의 첫 판정·보정·재대조 기록, 8방향 코드
- [source-checks.json](source-checks.json): 50자의 원문 해시·획별 시간·XML 참조·좌표 변환
- [originals.json](originals.json): 고정한 라이선스 원본의 중간선과 정규화 경로
- [proposals.json](proposals.json), [corrections.json](corrections.json): 획별 원본 대응과 국소 보정 이유
- [candidate-paths.json](candidate-paths.json), [review.json](review.json): 승인 경로와 증거 해시
- [prepare.mjs](prepare.mjs): 읽기 전용 승인 데이터 재현 (50자 승인을 검사)
- [verify.mjs](verify.mjs): 재현 결과·공개 데이터·적용 수·다음 후보 검증. 1급 회차의 보류 글자는 큐에서 뺀다
- [checks.json](checks.json), [progress.json](progress.json): 이번 검증과 전체 진행 현황
- [next-batch.json](next-batch.json): 다음 狐~洽 50자·559획 후보
- [acquire.mjs](acquire.mjs), [source-checks.mjs](source-checks.mjs), [serve.py](serve.py): 원본 고정·원문 확인·검토 시트

필순 근거는 e-hanja 사전이며, **한국어문회 인증으로 표시하지 않는다.**
재생 중간선은 Arphic Public License의 고정 MM·Ja 원본에서 출발했다.
사전의 경로·마스크·영상·스크린샷을 파일에 저장하거나 배포하지 않았다.
자형의 구조와 진행 방향을 비교한 것으로 폰트 외곽선의 픽셀 일치나 필기 채점이 아니다.

```bash

```

1급 **985/1,145자(86.0%)**, 남은 **160자**. 검토 가능한 미검토 1급은 **53자**다.
